# E-paper typography

Femto uses Rustybuzz for glyph selection and positioning and Swash for rasterization. Shaping remains independent of display refresh modes. Raster controls change the pixels without changing glyph advances, line breaks, bookmarks, or reading positions. Font size currently means physical framebuffer pixels; a point-size UI will require a verified panel density.

The grayscale raster path uses one coverage value per pixel. RGB subpixel rendering is not used. The vendored Swash 0.2.6 patch changes its internal Skrifa hinting mode from horizontal LCD to grayscale smooth hinting. Linear metrics remain preserved so the rasterizer and Rustybuzz use consistent advances. Swash exposes a hinting switch but does not expose this internal mode through its public scaler API. The patch is limited to that mode and its unused import.

## Controls

| CLI option | Default | Behavior |
| --- | --- | --- |
| `--text-hinting true/false` | true | Enable or disable outline hinting |
| `--text-stroke N` | 0 | Add 0 to 0.75 physical pixels of outline weight without changing advances |
| `--text-gamma N` | 1 | Apply coverage exponent 0.3 to 3; values below one darken edge pixels |
| `--fractional-text true/false` | false | Use fractional horizontal origins with grayscale coverage; otherwise round each shaped glyph origin |
| `--levels 2/4/256` | 256 | Select framebuffer grayscale levels |

`read` persists the text raster controls in reader state. Omitted controls retain the saved values. Older state files load neutral defaults. Display levels are currently a command-line selection, not a measured panel profile.

Images use ordered dithering. Text uses nearest-level quantization after all glyphs have been composited, preserving overlaps and combining marks. This avoids introducing a spatial dither pattern into thin glyph strokes. At two levels, faint strokes can still disappear; hinting, outline weight, and coverage controls must be compared on the actual panel. Coverage gamma is a tuning parameter, not an assumed LCD gamma or a measured e-paper transfer function. Four-level framebuffer values are nominal; the driver must map them to panel-specific waveform levels.

Outline weight is bounded but can close counters or reduce spacing at small sizes. Fractional placement preserves shaped spacing more closely but changes edge coverage. Neither option has been established as the best Picco default. The neutral profile adds no outline weight and no coverage adjustment.

## Line metrics

Line boxes use the regular face's ascender and descender as a minimum, then expand to include each selected style or fallback face. Shaped glyph outline bounds and vertical offsets extend the box when stacked accents exceed the font metrics. The configured line-height multiplier sets a minimum advance based on the largest font size in the line. Additional space is divided equally above and below the metric box. All runs share a baseline; font size alone no longer determines its position. These changes can alter page boundaries, while saved source anchors remain valid.

The paginator reserves the complete line box before placing it. A line taller than the reading area returns a layout error instead of clipping its content. This geometric bound covers unhinted outlines; hinting, pixel rounding, added stroke weight, and physical ink spread can extend raster coverage beyond it. Font line-gap recommendations are not added separately. Host tests cover tight spacing with stacked accents, Arabic/Hebrew text, descenders, mixed sizes, and unchanged baseline alignment. Physical spacing and raster-edge clearance remain unqualified.

## Chapter stylesheets

The shared EPUB loader collects linked stylesheets and XHTML `style` elements in document order. Embedded text, CDATA, and XML character/entity references pass through the same CSS subset as linked resources. Element-level `style` attributes retain their existing precedence. Stylesheet text is excluded from reading content. The public book stylesheet APIs and reader preparation use the same source collector, including the scratch-buffer path.

The collector accepts absent or `text/css` types and absent, `all`, or `screen` media. Print-only styles and other types are skipped. Complex media queries, CSS imports, alternate stylesheet selection, and embedded font discovery from chapter-local `@font-face` rules remain unsupported. Existing selector and cascade limitations still apply. Linked CSS uses its archive path; embedded CSS receives a chapter-relative diagnostic marker.

A chapter has at most 256 stylesheet sources. Linked and embedded CSS share a chapter-wide byte budget of 128 KiB in the interactive reader. External reads use the remaining budget, and embedded sources consume the same counter. Parsed rules share the existing 4096-rule limit across the chapter; parsing stops before retaining an excess rule. Failed stylesheet loads clear partial rules and counters. Invalid XML, unresolved entities inside CSS, nested markup in a style element, and unclosed style elements return errors. Limits on source descriptors and embedded bytes do not establish a complete parser-memory budget or physical Picco heap qualification.

The `embedded-css.epub` fixture checks alternating linked/embedded sources, CDATA, inline overrides, media/type filtering, and API agreement. Parser tests cover entity decoding, aggregate byte limits, source-count limits, and malformed inputs.

## Image size limits

Images accept CSS `max-width` and `max-height` in nonnegative pixels or percentages, plus unitless zero. `none`, `initial`, and `unset` remove the CSS limit. Tag and class rules, linked and embedded stylesheets, and inline declarations use the existing cascade subset. Limits apply to the image itself and do not inherit from its parent. Invalid or unsupported declarations leave preceding valid declarations intact.

Percentage limits use the fixed page content area after subtracting reader margins. The reader flattens nested containers, so this does not implement general CSS containing-block layout. Without CSS width, height, or a positive minimum dimension, each image retains the existing aspect-preserving fit within intrinsic dimensions, HTML dimension hints, CSS limits, and page bounds, without enlargement. Resets remove only the CSS limit; HTML hints still apply. Limits round down to whole framebuffer pixels. A zero maximum without a positive minimum on the same axis suppresses the image placement and its placeholder, and rasterization does not request the asset. Chapter loading can still probe its header.

The `image-limits.epub` fixture covers cascade precedence, non-inheritance, simultaneous limits, percentage reflow, resets, HTML hints, zero limits, and viewport clamping. Eager, indexed, resumed, forward, and backward pagination share the same geometry. Explicit `inherit`, font-relative units, `calc()`, and nested containing blocks remain unsupported for image sizing. Host rendering does not establish physical image quality or device decode budgets.

CSS `width` and `height` accept nonnegative pixels, percentages, and unitless zero. `auto`, `initial`, and `unset` select automatic sizing and suppress an HTML hint on the same axis. An unspecified CSS axis can still use its HTML hint. These declarations do not inherit implicitly. The parser preserves absent HTML hints when CSS sizing is present instead of replacing them with intrinsic dimensions. Percentages resolve against the fixed page content area, including percentage heights; nested container height calculations are not implemented.

One automatic axis derives from the image's intrinsic ratio, following the basic [replaced-element sizing model](https://www.w3.org/TR/CSS2/visudet.html#inline-replaced-width). With two specified axes, the authored box can change the image's proportions. Two specified axes apply their CSS maxima independently; an automatic axis retains proportional reduction under maxima. The resulting box scales down uniformly to fit the page and the one-megapixel resize-buffer limit. Explicit dimensions can enlarge the image. Area resampling supplies the enlarged or reduced pixels through the existing grayscale path. This bounded page fit is a reader policy, not complete browser CSS sizing behavior. Positive fractional results occupy at least one pixel; a zero dimension without an effective positive minimum suppresses both placement and missing-image placeholder.

The `image-dimensions.epub` fixture checks stylesheet cascade, width percentages, height-only proportions, explicit aspect changes, enlargement, HTML-hint resets, non-inheritance, and zero-size missing assets. Tests render at two viewport widths and compare every page reconstructed from its source anchor with the eager page pixels. Constructed extreme values verify finite-value rejection and page/resize-buffer bounds before integer conversion.

The [2026-11-08 image-dimension evidence](../tests/evidence/image-dimensions-2026-11-08.json) records 201 reader tests, 278 parser tests, workspace Clippy, and a monochrome Picco build. The final resize-buffer cap has a separate five-test image run after the broader reader run. These checks do not establish physical rendering or device peak memory.

CSS `min-width` and `min-height` accept nonnegative pixels, percentages, and unitless zero. `initial` and `unset` reset the minimum to zero. They do not inherit. Invalid declarations preserve earlier valid values. Minimum dimensions take priority over author maxima on the same axis. Automatic sizing preserves the intrinsic ratio where the constraints permit it; incompatible minima and maxima can change the proportions. Two specified dimensions clamp independently. This follows the constraint model in [CSS 2.1 replaced-element sizing](https://www.w3.org/TR/CSS2/visudet.html#min-max-widths), with the existing paged-layout policy: percentage heights use page content height, and page bounds and the resize-buffer limit still override author minima.

The `image-minimums.epub` fixture exercises enlargement, conflicting constraints, zero-width recovery, percentage minima, non-inheritance, resets, invalid overrides, and hidden missing assets. Tests compare exact dimensions at two viewports and rasterized pages reconstructed from source anchors. Constructed nonfinite, negative, and extreme minima test rejection and allocation bounds.

The [image minimum evidence](../tests/evidence/image-minimums-2026-11-08.json) records the complete repository gate, Bluetooth-enabled monochrome firmware build, source hashes, and five-page four-level host preview. Hardware rendering remains unverified.

## Lists

Ordered lists accept case-sensitive `type` values `1`, `a`, `A`, `i`, and `I`, as defined by the [HTML numbering hints](https://html.spec.whatwg.org/multipage/rendering.html#lists). An item-level type changes only that item in its ordered list. Type and value attribute order does not affect the result. Nested lists start with their own decimal style unless overridden. Alphabetic numbering uses Latin letters and continues from `z` to `aa`. Nonpositive alphabetic values and Roman values outside 1 through 3999 fall back to decimal, following the [CSS counter definitions](https://www.w3.org/TR/css-counter-styles-3/#predefined-counters). The prototype ignores item type hints in unordered lists. Custom counter definitions are not implemented.

The supported [CSS list-style-type](https://www.w3.org/TR/css-lists-3/#list-style-type-property) values are `disc`, `circle`, `square`, `decimal`, `lower-alpha`, `upper-alpha`, `lower-latin`, `upper-latin`, `lower-roman`, `upper-roman`, and `none`. Declarations inherit through element context and use the existing stylesheet/inline cascade subset. Local CSS overrides HTML type hints. `initial` selects disc; `inherit` and `unset` use the parent style. Ordered and unordered list elements establish decimal and disc defaults unless overridden. Styles can select numeric markers for unordered items without changing their item counts. `none` suppresses the marker while retaining the list column and counter. Invalid declarations preserve the preceding valid value. The `list-style` shorthand, image markers, custom strings, `list-style-position`, and general CSS counters remain unsupported.

Textual `ol` and `ul` items retain their list type and nesting depth. Ordered lists use decimal markers starting at one unless `ol start` supplies a signed number; unordered lists use a bullet. An `li value` overrides its number and the following sequence within its ordered list. Unordered lists ignore these attributes. Signed 32-bit attribute values, zero, surrounding ASCII whitespace, and XML references are accepted; invalid or overflowing values retain the ordinary sequence. Counters use wider storage so incrementing a maximum attribute does not overflow. Nested lists have independent counters. The `reversed` attribute changes the step to minus one. Without a valid explicit start, a reversed list starts at its direct child item count, including empty items. An explicit item value changes the current number while preserving the descending step. The first text paragraph in each item carries the marker, and later paragraphs retain the item depth without repeating it. List and item stacks are limited to 16 levels. Reversed lists use a preliminary XML pass keyed by element offsets. It skips non-reading elements and retains at most 1024 list counts, with at most 16 nested reversed lists and 16,384 direct items per reversed list. Documents without the reversed attribute text skip this pass. These are software bounds; physical heap usage remains unmeasured.

Markers are shaped separately from paragraph text and rendered in a reserved area at the paragraph start edge. Wrapped lines share the reduced text column. The reserved area grows with nesting up to half the column width, and expands further when needed to contain a wide marker. A marker wider than the reading area returns an error. RTL paragraphs place markers on the right. Marker metrics contribute to the first line's height, and marker glyphs count toward the page glyph limit.

Markers do not become source text, link targets, or underline targets. Page reconstruction from a paragraph continuation omits the marker while preserving the text column. The `lists.epub` fixture covers nested lists, continuation paragraphs, RTL text, linked text, and a multi-page item. The `list-numbers.epub` fixture covers sequence overrides, signed boundaries, nested counters, invalid input, and continuation alignment after a wide marker. The `list-reversed.epub` fixture checks default counts, nested lists, explicit starts, item overrides, empty items, and signed counter boundaries. The `list-types.epub` fixture checks alphabetic boundaries, Roman subtraction and range fallback, item overrides in both attribute orders, nesting, continuation labels, reversed counters, and page reconstruction. Separate fixtures verify the nesting limit. The `list-css.epub` fixture checks CSS/HTML precedence, inheritance and resets, marker suppression, nested defaults, unordered numeric markers, empty-item counting, and reversed alphabetic sequences. Empty and image-only item markers and marker alignment across differently styled items remain unfinished.

## Paragraph indentation

The EPUB subset supports positive and negative `text-indent` values in `px`, `em`, and percent, plus zero, `initial`, `inherit`, and `unset`. Stylesheet and inline declarations use the existing cascade subset. Indentation belongs to the containing block; an inline span's declaration does not change its paragraph's indent. Em values resolve against the declaring element's font size and retain that computed length through inheritance. The existing parser's font-size approximation and configured font-size bounds still apply. Reader font-size changes scale em indents. Pixel lengths use framebuffer pixels, and percentages use the text column width.

The first source line reserves space at the paragraph start edge before line breaking, alignment, and justification. This is the left edge for LTR paragraphs and the right edge for RTL paragraphs. Subsequent lines, including a page reconstructed from a mid-paragraph source anchor, use the full column. Source offsets do not include synthetic spaces. Oversized positive values are capped to leave one base-font em of column width. Negative values extend the first line into the reader margin and are capped at that margin's width. In list items, the first-line marker moves outward with a negative indent to preserve its gap from the text. These bounds apply to glyph advances; glyph ink overhang can still be clipped at the framebuffer edge. Invalid declarations preserve an earlier valid declaration. The `hanging` and `each-line` keywords, `calc()`, other units, inline formatting contexts, and complete CSS cascade behavior remain unsupported. The supported behavior follows the basic first-line case of [CSS Text indentation](https://www.w3.org/TR/css-text-3/#text-indent-property), with explicit positive and negative caps for the bounded reader viewport.

`tests/fixtures/indent.epub` covers block inheritance, em computation across a font-size change, inline isolation, reset values, signed percentages, inherited negative computed lengths, and RTL text. Host tests check line widths, both start edges, continuation lines, page reconstruction, and negative list indents with marker separation. Physical readability remains unqualified.

## Language-aware line breaking

In Book mode, each text span selects automatic hyphenation for English, German, French, Spanish, Italian, Dutch, and Portuguese, using the two-letter primary language tag without case sensitivity. Selection uses the pinned crate's ISO-code lookup and only explicitly enabled pattern sets. XHTML language declarations override the book metadata default. Regional tags share one enabled pattern set per language: American English, reformed German, French, Spanish, Italian, Dutch, and Portuguese. Distinct regional patterns are not selected. Unknown languages and TXT documents with `und` metadata use ordinary Unicode line breaks. Generated menu and image-placeholder labels do not use dictionary hyphenation. Broader locale/font validation remains unfinished.

The shared Typography menu has an Auto hyphens control on its second page. It cycles through Book, Off, English, German, French, Spanish, Italian, Dutch, and Portuguese. Book follows XHTML language inheritance and book metadata; an explicit language selects its dictionary even for untagged TXT text. Off disables automatic dictionary candidates while retaining author-supplied soft hyphens. Every mode retains CSS `hyphens: manual` and `hyphens: none` restrictions. The override does not change source text, language metadata, Rustybuzz language selection, or bidi analysis. It is saved with each book’s typography preferences.

Changing the mode starts cancellable cooperative reflow. The previous mode and page stay active until reflow completes; cancellation leaves both unchanged. Completion retains the source anchor and persists through the normal frontend state path. Layout JSON stores `hyphenation` as a named mode; old state without the field defaults to `book`, and unknown modes are rejected. Menus and generated image labels do not gain dictionary breaks from this setting. Tests cover untagged-language selection, automatic-Off with retained soft hyphens, CSS restrictions, cancelled and completed reflow, saved-state reload, and native pointer selection without moving the source position. Shaping-language overrides remain separate work.

The paginator first measures ordinary break opportunities. When the next word overflows, it tries dictionary breaks beyond the last fitting ordinary break and measures the additional hyphen glyph. Breaks preserve grapheme boundaries. The hyphen uses the preceding text style, font selection, and grayscale raster path. Automatic hyphens currently apply only when the candidate line contains no right-to-left levels; mixed-direction and RTL lines retain the existing Unicode/emergency behavior. Author-supplied soft hyphens have a separate shaping path described below.

Source text remains unchanged. Each line exposes `hyphenated` separately from its source `text`, and a dictionary-inserted glyph maps to the preceding source character. Page locators, bookmarks, and links continue to use original byte offsets, including after reflow. Raster weight and coverage controls do not affect the measured hyphen or line selection.

Patterns are read directly from static tables. Dictionary lookup skips words longer than 128 source bytes. Non-ASCII words use NFC-normalized lookup text from the existing pinned `unicode-normalization` dependency. A map from normalized grapheme ends to original byte offsets translates dictionary candidates back to the source. Candidates inside a grapheme are discarded. The alphabetic-character check applies after normalization, so decomposed accents that compose into letters no longer disable automatic hyphenation. Other nonalphabetic lookup characters still disable it. ASCII lookup borrows the source without allocating a normalization buffer or offset map. Normalization does not change shaping input, language selection, CSS restrictions, or saved source locations. The source-byte limit applies before normalization, so equivalent spellings that fall on opposite sides of that limit can still differ.

A paragraph retains at most 32,768 candidate offsets; subsequent words fall back to ordinary breaking. The offset storage is at most 128 KiB on the 32-bit device or 256 KiB on a 64-bit host, excluding vector bookkeeping and other layout allocations. Non-ASCII dictionary lookup also retains one bounded word buffer and at most 128 grapheme offset pairs. Repeated line lookup uses binary search into candidate offsets. Existing page, glyph, and emergency-line limits remain in effect. These are software bounds; peak device heap usage remains unmeasured.

Tests cover English/German/French/Spanish/Italian/Dutch/Portuguese breaks, measured hyphen width, original source coverage, glyph clusters, reflow positions, unknown languages, combining sequences, and oversized words. The pinned dependency builds for ESP32-S3. Physical reading quality and language-corpus validation remain unverified.

The [canonical-accent regression](../tests/evidence/canonical-hyphenation-2026-11-08.json) compares composed and decomposed Portuguese, German, and French words. It checks identical normalized line text and hyphen decisions, original byte coverage, grapheme-boundary breaks, glyph source offsets, reflow anchors, and raster equality after resuming each page from its original locator.

## XHTML language inheritance and shaping

The vendored EPUB styled-event parser retains `lang` and `xml:lang` on elements and resolves the nearest declaration for each text run. `xml:lang` takes precedence when both attributes appear on an element. An empty declaration represents an unknown language and clears an inherited value. Closing a nested element restores its parent's declaration. The reader uses book metadata only for runs with no inherited declaration. TXT metadata remains `und` unless a caller supplies a language.

Language attributes are XML-unescaped, normalized to lowercase, and limited to 63 bytes. Nonempty values must contain hyphen-separated ASCII alphanumeric components of one to eight bytes. Invalid lexical forms and oversized attributes reject the chapter. This is a bounded lexical check, not complete BCP 47 registry validation. The limit applies to retained language values; XML decoding still uses the chapter's broader input limits. Each span stores its resolved language, so language memory grows with the existing bounded event count. Peak device memory remains unmeasured.

Rustybuzz receives each shaping segment's language, resolved script, and bidi direction explicitly. This allows a font's localized OpenType substitutions to operate. A test checks that DejaVu Serif selects different Cyrillic small-be glyphs for Serbian and Russian and that `sr-Cyrl` selects the Serbian form. Language tags do not select a different font family. Coverage-based fallback does not rank fonts by language or script preference.

Hyphenation evaluates complete words across style spans. A change of language inside a word disables dictionary hyphenation for that word; it does not apply separate dictionaries to word fragments. Unsupported or explicitly unknown languages retain ordinary breaks and author-supplied soft hyphens. The `language.epub` fixture covers metadata fallback, German/French overrides, an empty override, Spanish, and nested restoration. Parser tests cover attribute precedence, escaped values, and bounds. The inheritance rules follow [XML language identification](https://www.w3.org/TR/xml/#sec-lang-tag) and [HTML language attributes](https://html.spec.whatwg.org/multipage/dom.html#the-lang-and-xml:lang-attributes).

## Script segmentation

A forward iterator resolves script runs in the document text block before line breaking, bidi ordering, style clipping, font fallback, and shaping. Script context therefore survives wrapped lines, directional runs, and changes of weight, size, emphasis, and language within the block. The resolved runs are clipped to each style span; font and language selection still apply independently to each clipped segment. The segmenter intersects Unicode Script_Extensions sets across grapheme clusters. Common and inherited characters remain in a compatible neighboring run; a neutral prefix adopts the first compatible script. An empty intersection starts a new run. A grapheme with incompatible marks remains intact and uses its first explicit script when available. Unknown-only graphemes remain with surrounding common context.

Matched brackets use the opening bracket's resolved script context when compatible with the closing grapheme. The segmenter reuses the pinned `unicode-bidi` bracket table, including normalized opening identities. A leading opening bracket adopts its run's first compatible script. Nested brackets retain their own context; a matching outer close discards unmatched inner openings. Script-specific combining marks can prevent a closing grapheme from inheriting an incompatible context. Grapheme boundaries remain intact.

The open-bracket stack holds at most 64 entries. A deeper nest clears the stack and disables pairing for the rest of that text block, retaining ordinary script segmentation and source coverage. Matching does not cross document text blocks. Style clipping uses a binary search for the first overlapping script run and visits only overlapping runs. Language-dependent quotation pairing is not implemented. Ambiguous extension sets use their first remaining script deterministically; language-based preference within an ambiguous set remains unfinished. This is a bounded shaping heuristic based on [Unicode Script and Script_Extensions](https://www.unicode.org/reports/tr24/), not a claim of complete Unicode text-layout conformance. Classification of a script does not establish that the chosen font or shaping engine supports it.

Font fallback then operates on complete graphemes within each script run. RTL runs reverse the logical script/font segment order before shaping, and every shaped glyph retains its original paragraph byte cluster. Line fitting shares a script window covering its next 4096 source bytes. The window retains at most 4097 run descriptors, including a run that starts before the current line, and discards earlier ranges. Allocation grows in chunks of at most 64 descriptors. A script run can extend beyond the window without retaining its characters or a paragraph-sized run table. A long homogeneous run can require scanning to the end of the block to resolve its extent. The existing chapter-input limit bounds imported text; bidi analysis still retains paragraph-sized data. Resuming pagination reconstructs context by scanning the prefix once, while skipping old runs without retaining them. Candidate line fits reuse the same window. All shaping calls enforce the same 4096-byte input limit, including synthetic list markers; an oversized marker returns an error before glyph generation. Peak device heap use still needs measurement.

Tests verify a localized Serbian Cyrillic glyph surrounded by Latin ligatures, Arabic joining in a mixed Hebrew/Arabic run, RTL visual order, shared Japanese marks, combining sequences, emoji ZWJ sequences, unknown code points, and complete source-range coverage. The `scripts.epub` fixture provides a visual specimen with the bundled serif and fallback sans fonts. `brackets.txt` adds nested, leading, Unicode, combining-mark, mixed RTL, and malformed bracket examples. `styled-brackets.epub` covers pairs across emphasis, size, and language boundaries. `wrapped-brackets.txt` exercises multiple lines and pages. Pagination tests compare eager, indexed, resumed, forward, and backward page geometry for these fixtures. Unit tests check resolved script ranges, complete byte coverage, and the exact nesting limit and overflow fallback. It can be rendered with the ordinary CLI render command. Host inspection and successful firmware compilation do not qualify all scripts or physical-screen rendering.

## CSS hyphenation controls

The EPUB CSS subset supports inherited `hyphens: none`, `manual`, and `auto` through stylesheet rules and inline declarations. `none` suppresses dictionary and soft-hyphen opportunities. `manual` permits author-supplied soft hyphens but disables dictionary lookup. `auto` permits both. Visible hyphen-minus and hyphen characters retain their normal break opportunities under all modes. The reader still uses its grapheme-preserving emergency wrapping for words wider than the viewport; disabling hyphenation does not disable that overflow behavior.

`inherit` and `unset` restore the parent element's policy even when a lower-priority declaration on the same element specifies another value. `initial` selects `manual`, following [CSS Text's initial value](https://www.w3.org/TR/css-text-3/#hyphens-property). Unspecified publisher styles retain Femto's existing automatic reader default. This is a reader default rather than the CSS initial value. Invalid values leave an earlier valid declaration intact. Vendor-prefixed properties, `revert`, cascade layers, and `!important` are not supported by this implementation; the existing stylesheet selector/cascade subset still applies.

Dictionary hyphenation is skipped when any span within a word uses `none` or `manual`. An explicit soft hyphen uses the policy of its own source span. Source text, offsets, and bookmarks are unchanged by these modes. Adjacent parser runs with identical style and language are coalesced before shaping so XML entities and redundant inline tags do not interrupt kerning or ligatures. The `hyphenation.epub` fixture covers stylesheet inheritance, inline overrides, numeric soft-hyphen entities, and source-preserving pagination. Tests also check all policy combinations, visible hyphens, CSS reset values, and the unbroken glyph sequence for `of&#173;fice`.

## Soft hyphens

U+00AD is omitted from the shaping buffer when a line continues through it. Original byte clusters are supplied explicitly to Rustybuzz, so removing the invisible character does not renumber following source positions. This preserves kerning, ligatures, and joined runs without depending on a font's soft-hyphen glyph. Font fallback keeps the invisible marker with the preceding segment.

When a line ends at a soft-hyphen opportunity, the shaper substitutes a visible hyphen-minus in that directional run and measures its advance. Its cluster points to the original U+00AD bytes, and its style comes from that source span. The visible mark takes the preceding word's bidi level; visual runs are reordered after this substitution to avoid the trailing invisible character's paragraph-level reset. Tests cover both an RTL paragraph and an RTL word within an LTR paragraph. A terminal soft hyphen at the end of a paragraph stays invisible.

Explicit soft-hyphen opportunities are merged with the pinned Unicode line-break iterator. This includes the Hebrew soft-hyphen break suppressed by that iterator's contextual rules. An overflowing discretionary candidate does not terminate the search: the complete word can be narrower than the prefix plus its displayed hyphen. Source text and line boundaries remain expressed in original bytes, and `Line::hyphenated` identifies lines with a displayed mark.

This implements the ordinary inserted-hyphen case of [Unicode UAX #14 section 5.4](https://www.unicode.org/reports/tr14/#SoftHyphen). Language-specific spelling changes, script-specific hyphen shapes, and duplication on the following line remain unimplemented. It does not establish full UAX #14 conformance. Raster-equality tests check unbroken soft hyphens across Latin ligatures, kerning pairs, and Hebrew fallback text. Other tests cover width selection, source offsets, span styles, paragraph endings, leading markers, and mixed-direction placement. The original `tests/fixtures/soft-hyphens.txt` provides a reproducible visual specimen through the CLI render command.

## Reference findings

The inspected [CrossPoint TTF implementation](https://github.com/crosspoint-reader/crosspoint-reader/blob/aa76a31b7bdc1d8a7dc7b24a57cf4815c1904d5f/lib/EpdFont/TtfEpdFont.cpp) configures FreeType auto-hinting and stem darkening and uses separate monochrome and two-bit coverage thresholds. Its comments explicitly discuss inconsistent stem weights during black/white turns. This source snapshot does not identify the cause of poor rendering in a different installed version.

The [FreeInk Picco display tests](https://github.com/Free-Ink/freeink-sdk/blob/567f448959c4379ecf7025b6abb00d8dbc70abec/libs/display/FreeInkDisplay/test/host/test_picco.cpp) exercise different panel IDs and full, fast, and grayscale waveform paths. A single universal Picco contrast curve is therefore not assumed.

[Swash rendering controls](https://docs.rs/swash/0.2.6/swash/scale/struct.Render.html) provide outline weight and fractional offsets. The local dependency source and Skrifa hinting implementation were inspected for the grayscale hinting change. Full monochrome hinting and an alternative FreeType raster backend remain candidates if the physical comparison shows that grayscale smooth hinting plus quantization cannot produce consistent black/white strokes. Engine replacement is not justified by the host PNGs alone.


The native simulator exposes these controls through the same typography menu as the Picco. Pointer and keyboard operations use `ReaderUi`, and changes persist in reader state. The X11 smoke test changes the font size, restores it, and opens another book through the shared library menu. Reflow selects the page containing the retained source anchor. Repeated size changes, saves, and reopen operations preserve that anchor until an explicit navigation action changes it. The native test checks exact position retention after increasing and restoring the font size. Bookmark toggling uses the same retained anchor.

## Per-book preferences

Font size, line height, margin, automatic hyphenation, and text raster controls are saved with the current book when a frontend records its position or the reader switches books. Books without saved preferences inherit the active settings, including legacy state files. Reopening a book restores its preferences before pagination. Viewport dimensions, rotation, frontlight, and sleep settings remain device settings. A book preference that cannot fit the current viewport rejects opening without changing the active reader.

Cooperative opening indexes and renders the destination with its saved settings before replacing the current book. Cancellation preserves the source settings and page. Changes to the destination preferences during indexing invalidate the pending opening. Host files and the alternating device journal validate saved preferences; startup and interactive opening use the same selection rules. Tests cover switching between different settings, rotated viewports, source anchors, startup pixels, cancellation, stale jobs, legacy files, and invalid persisted values. Physical screen calibration remains unfinished.

The [raster persistence regression](../tests/evidence/raster-persistence-2026-11-08.json) saves nondefault hinting, stroke, coverage, and fractional-position settings through host JSON and the device journal. It reloads each with neutral active settings so only the saved book preferences can restore tuning. Cooperative startup must reproduce every logical framebuffer pixel at two and four levels in each orientation. The test also requires tuned output to differ from neutral output, checks the permitted gray values, and verifies that raster tuning preserves the source anchor and page counts. These checks cover logical viewport rotation; physical panel packing and perceived text quality require separate qualification.

The second Typography page includes Reset book typography. It restores the built-in font size, line height, margin, hyphenation mode, and raster controls through one cooperative reflow. The old layout and raster remain active until the destination page renders successfully. Cancellation preserves both. A concurrent raster change invalidates a pending reflow. Reset retains the source anchor, viewport dimensions, and device orientation. Normal frontend persistence saves the defaults as this book’s preferences. Reset on an already-default book performs no work.

The second Typography page also provides Line spacing and Margins controls. Line spacing cycles through 1.00, 1.15, 1.35, 1.60, and 2.00. Margins cycle through 0, 8, 16, 24, 32, 40, and 48 logical pixels on all sides. Each control advances to the next larger preset and wraps to the smallest. Presets that fail the current viewport and font-size reading-area checks are skipped. Changes use cancellable cooperative reflow, retain the source anchor, and persist as per-book preferences through the normal frontend save path. These presets are UI choices, not physical panel calibration results.

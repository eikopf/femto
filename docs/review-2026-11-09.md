# Software review: 2026-11-09

The review covers UDP ingress, network queue handling, identity record reads, diagnostic output, and selected reader allocation boundaries. It is a source review with regression tests, not a complete security audit or a physical resource qualification.

## Changes

The shared UDP poller previously copied each datagram into a new vector before passing it to the authenticated network owner. It now reuses caller-owned storage. The allocating compatibility API delegates to the same bounded receive implementation. Both APIs preserve the extra-byte truncation check. Tests cover empty, maximum-sized, oversized and subsequent short datagrams, nonblocking reads and closed sockets.

Host identity and pending-rotation records previously used growing zeroizing vectors. Zeroizing a vector on drop does not cover allocations relinquished during its growth. Record reads now use fixed-size zeroizing arrays, including an extra byte for oversized-record detection. Fragmented reads and interruptions retain their previous semantics. This reduces secret-buffer allocation and avoids growth in these reads; it does not establish erasure of all cryptographic copies or freed physical memory. The existing private-directory and exclusive-owner contract still applies. This change does not harden pathname operations against a malicious process running as the same user.

[Network diagnostics](diagnostics.md) expose fixed-size, saturating counters and current packet-buffer capacities. The host API uses the existing control lock. Picco logs a bounded-frequency snapshot during active polling. No packet-level logging or diagnostic network service is added.

## Reviewed boundaries and remaining work

| Area | Observed boundary | Remaining measurement or review |
| --- | --- | --- |
| Network queues | 16 outgoing packets, 8 incoming packets, bounded datagrams; authorization and expiry are checked before release | Physical heap, stack and allocator fragmentation under sustained traffic |
| Identity records | Exact-size decoding, private file permissions, exclusive owner, zeroizing record buffers | Same-user pathname races, platform storage guarantees and physical erasure |
| Basic credentials | Origin-scoped header, explicit HTTP opt-in, redacted Debug, bounded credential input | Redirect and service compatibility beyond existing fixtures |
| PNG/JPEG | Encoded byte, dimension and pixel limits; PNG decoder allocation limit | Interlaced frame plus grayscale output and decoder internals can coexist; limits are not peak-heap measurements |
| Glyph cache | 64 KiB of cached mask capacities and 256 entries per page | Container overhead and an oversized uncached glyph are additional; eviction scans the bounded entry set |
| Dictionary | File/count/query limits and bounded definition cache | Decoder and third-party parser allocation peaks |
| Saved state and library cache | Bounded reads; library scan limit is validated before cache-size arithmetic | JSON object allocation can exceed encoded bytes; library entry validation follows deserialization |

No latency or physical heap improvement is claimed from source inspection. The UDP change removes an identifiable allocation/copy site. Device throughput, peak heap, stack high-water marks, sleep behavior and display timing still require hardware access. Earlier reproducibility evidence remains bound to its recorded source inventory and does not qualify these new changes.

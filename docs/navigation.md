# Reader navigation

Contents entries retain their navigation document path as the URI base. Selection resolves the entry relative to that path, finds the declared XHTML document, and resolves its fragment against the chapter's rendered source locations. EPUB 3 navigation and NCX base selection follow the parser's manifest priority. A contents file under `nav/` can therefore link to `../text/chapter.xhtml#section`.

The document adapter records `id`, `xml:id`, and legacy anchor `name` attributes. Pending anchors bind to the next visible text or image, after structural paragraph boundaries. Inline anchors retain byte offsets in the paragraph. Duplicate IDs retain the first location. Empty trailing anchors resolve to the end of the chapter. Skipped content does not create a visible target.

Hyperlink text retains a source range and its raw document-relative target. Adjacent styled runs with the same target merge into a single link label. Linked images use their image location and alt text. The current page exposes links whose source ranges overlap its range. Both frontends select these links through a list or a direct tap on the reading page.

The interactive reader underlines linked text with black pixels after text quantization. The underline follows each shaped cluster's advance and source range, including reordered bidi runs, ligatures, and expanded justification spaces. Its thickness scales with font size, with a minimum of one logical display pixel. Decoration does not alter line breaks, page boundaries, source anchors, or text raster settings. It marks unsupported targets as links too; selecting such a target still returns the existing resolution error. Linked images retain direct tap support but have no added decoration. Low-level layout exports do not add these interactive reader underlines. Font-specific underline metrics, descender avoidance, author decoration styles, and physical panel legibility remain unqualified or unimplemented.

Direct taps use logical display coordinates after the frontend's orientation transform. Text targets use positioned glyph advances horizontally and the measured line ascent/descent around its shared baseline vertically. Style and fallback metrics and shaped accents contribute to those vertical bounds. Extra leading and paragraph gaps are excluded, so a target does not extend into a neighboring line. Source cluster ranges are derived in logical order, independently of visual bidi order. A ligature whose source range overlaps a link activates that link. Zero-advance marks do not create separate targets. Justified spaces include their expanded advance. Image targets use the placed image rectangle, including placeholders. Horizontal targets remain approximate: italic overhangs and marks outside their base glyph advance are not separate targets. Physical touch target sizing remains unqualified.

A link tap takes precedence over page-turn and menu zones. Taps outside link targets retain those zones. Link resolution uses the same transactional navigation and Back history as the link list. Unsupported or missing targets return an error without a page turn. Host fixtures cover navigation after font-size changes, reordered Hebrew clusters, Latin ligatures, linked images, viewport boundaries, tall stacked accents, mixed font sizes, line gaps, and Back history.

URI resolution splits the fragment before percent decoding, validates UTF-8, resolves relative path segments, and compares canonical paths to spine entries and declared supplemental XHTML documents. Absolute paths, network schemes, authority URLs, backslashes, queries, malformed escapes, and archive-root traversal are rejected. Navigation never fetches a network URL or opens a host path. Each URI or navigation attribute is limited to 4096 bytes. Existing chapter byte and event limits also bound anchors and links.

The controller resolves and paginates a target before replacing the visible page or adding back history. A missing anchor or unsupported target returns an error and preserves the current page and history. Font-size changes retain source locations; fragment selection finds the page containing the target under the new layout. Up to 64 jump origins are retained in memory. History is not persisted across process restarts; the reading position and bookmarks are persisted.

The reader retains a source anchor independently of the displayed page's start. `Reader::position` returns that anchor. Reflow selects the containing page without replacing the anchor; saving, reopening, and switching books preserve the same byte location. A successful page turn sets the anchor to the new page's start. Contents, links, bookmarks, and chapter selections set it to the resolved target. A jump within the same displayed page still updates the anchor and records its previous value in back history. Bookmark toggling operates on the retained anchor, so reflow does not create a second bookmark at a new page boundary.

Resume targets are checked against the selected page's source ranges and UTF-8 character boundaries. Invalid offsets fall back to that page's start; an invalid chapter falls back to the book's beginning during open. Image locations are accepted directly. The existing persisted locator format is unchanged. Previously saved page-start positions remain valid, but positions already lost through earlier reflow cannot be reconstructed.

Footnotes use internal-link targets and optional paged previews. Following a footnote opens its containing page. Back returns to the reading page, and explicit return-reference links also work. Manifest-declared XHTML documents outside the spine open through the same bounded parser and renderer, including stylesheet and image resolution relative to their own paths. Normal page turns stay within a supplemental document; Back or a return-reference link leaves it. EPUB CFI, media overlays, and external browser launch are not implemented.

Supplemental documents receive deterministic indices after the spine, sorted by canonical path, with at most 4096 supplemental entries. The book content hash identifies saved state, so positions and bookmarks in these documents remain stable when reopening the same file. Supplemental documents do not appear in the chapter chooser or extend ordinary spine page turns. Missing, undeclared, non-XHTML, and external targets remain errors.

`tests/fixtures/supplemental-notes.epub` tests non-spine note selection, page-turn boundaries, bookmarks, reflow, save/reopen, and explicit return links.

## Whole-book progress estimate

The shared root menu displays `Reader ~N%`, and terminal reading status displays `book ~N%`. The estimate measures progress through the visible page. EPUB spine documents are weighted by their uncompressed XHTML sizes from the ZIP directory; the current chapter contributes the fraction of its indexed pages through the visible page. This avoids decompressing or paginating other chapters to calculate progress. TXT uses its single chapter. A final spine page reports 100%; earlier pages remain below 100%.

The estimate is not a reading-time measure or a whole-book page count. Markup density, images, font size, and line layout affect its accuracy. Reflow can change the estimate while preserving the exact saved source location. Supplemental footnotes have no percentage and do not contribute to the denominator. Missing size metadata or arithmetic failure hides the estimate without preventing reading. At most 4096 64-bit chapter weights are retained, within the existing spine limit; allocator overhead and device latency remain unqualified. No percentage is persisted or used for progress synchronization.

Tests cover unequal chapter weights, real EPUB ZIP sizes, monotonic page turns through chapter boundaries, the final page, chapter jumps, reflow, absent metadata, overflow, and supplemental-note reopen. The native simulator uses the same menu label as the Picco.

`tests/fixtures/navigation.epub` includes a nested navigation document, cross-chapter footnotes after several pages of text, an inline anchor, an escaped anchor attribute, styled link text, an external URL, and a missing target. Tests verify source ranges, percent decoding, traversal rejection, contents/link selection, repeated reflow with save/reopen, same-page jump anchors, bookmark toggling, back history, book switching, invalid resume offsets, and terminal commands. The native simulator uses the same controller actions; its separate Xvfb smoke test verifies native menu input and reading-state persistence.


Direct page turns that fail while opening a destination chapter retain the current page and show a recoverable menu error. The previous-page action and library menu remain available. Firmware also converts errors from input dispatch into menu errors instead of stopping the reader.

## Go to, status line and sleep page

This book, Go to lists places 5% of the book apart and opens on the one being read. Choosing one moves to the chapter that holds that share of the book by the same weights as the progress estimate, and within it to the block at the matching share of the chapter's blocks, so the page reached is approximate. Return from jump goes back.

Settings, Status line shows the progress estimate at the bottom left of the reading page and the battery charge with a small cell symbol at the bottom right. The layout keeps the bottom 32 rows free of book content for it (`LayoutConfig::footer`); these overlap the bottom margin, so a deeper margin is unchanged and a shallower one gives way. The line is drawn only when the page is, and adds no display refreshes. Changing the setting lays the book out again.

The sleep page is the book's cover, reduced to fit the screen and centered; a smaller cover keeps its size. A cover may be larger than an image on a page, up to four megapixels, since it is decoded when little else is; its pixels are allocated fallibly with room to spare, so a cover the device has no memory for is refused and not fatal. A progressive JPEG over one megapixel is refused, because it needs memory for every coefficient at once. A book with no cover, or with one refused, shows its title, author and progress as before.

Host tests cover all three. On the Picco the status line and Go to were checked from framebuffer dumps; the cover sleep page was not, because the framebuffer cannot be read while the reader sleeps.

## Persistent library metadata cache

The simulator and Picco load `.femto-library-cache.json` from the configured library root without traversing folders or hashing books at startup. Cached paths, content IDs, titles, authors, and languages populate the library immediately. Rescan discovers additions and removals and verifies content hashes. The cache does not hold chapter layout or rendered pages.

Warm opening compares the selected file handle's size and modification time with its cached stamp. A match reuses the cached content ID without reading the entire file. A missing or changed stamp triggers a full SHA-256 calculation and refreshes the entry after metadata parsing. The parser uses the same open handle. Cache write failures leave reading available. Ordinary `Document::open`, staged-download validation, and sync verification retain full hashing. A same-size edit with a restored or indistinguishable timestamp remains undetected on warm opening until Rescan. Cache stamps are a performance policy, not content authentication.

Cache version 2 adds file size and modification time. Version 1 metadata remains usable for browsing, but its first opening requires hashing before recording a stamp. The index is bound to the canonical library root. Loading and serialization limit encoded data to the smaller of `limit * 4096 + 1024` bytes and 4 MiB. Counts, metadata lengths, paths, duplicate paths, and content-ID syntax are checked. Canonical target checks reject opens outside the selected library.

A completed, nontruncated scan with no traversal failure atomically replaces a changed index through a sibling temporary file. An unchanged valid index is not rewritten. Cancelled, failed, truncated, and traversal-incomplete scans do not publish partial indexes. The reserved index filename and its temporary files do not consume the book limit. Corrupt, oversized, unsupported, misplaced, or unreadable indexes produce a bounded scan diagnostic and fall back to normal parsing. A failed cache write leaves discovered books available. Read-only libraries remain readable.

After the root directory opens, directory-entry errors, file-type lookup failures, and unreadable subdirectories produce diagnostics and allow traversal of accessible siblings to continue. Exceeding the directory-depth limit has the same cache-preservation behavior. Directory iterator errors count toward the traversal work limit. Diagnostics retain the existing limit of 64 messages and 512 characters per message. The completed library contains accessible books and exposes the diagnostics through Scan errors; it does not include stale entries from inaccessible folders. Delete a book in the Library menu lists the books; choosing one asks for confirmation, with Keep book selected first, then removes the file and its cached library entry. The file must be a regular file inside the library folder, and the open book cannot be deleted. Saved positions, bookmarks and clippings for a deleted book are kept. The entry is offered only when a library folder is configured. Root canonicalization and root opening failures still fail scan creation. These behaviors do not establish a filesystem snapshot or physical SD-card removal handling.

The [library traversal fault regression](../tests/evidence/library-traversal-2026-11-08.json) checks an unreadable child directory in cached and uncached scans, available sibling books, unchanged cache bytes, and metadata reuse after permissions are restored. The permission case requires Unix permission enforcement and reports a skip when the process can bypass directory permissions. A separate depth-limit test verifies that an incomplete scan retains newly discovered accessible books without replacing the previous complete cache, then publishes the updated cache after a complete traversal.

Explicit scans traverse the current directory tree and hash every candidate book. Matching content IDs reuse cached metadata; changed IDs require parsing. This detects changes even when file size and modification time are preserved. Each step processes one directory entry or a five-millisecond batch of 8192-byte hash reads. Cache I/O, parsing, and individual filesystem calls remain synchronous and can exceed that budget. Full-scan cost scales with total book bytes, but startup no longer waits for it. Concurrent file changes remain outside snapshot guarantees.


The internal `FileHash` state owns the open file throughout cooperative hashing. EOF produces the computed identity and parser-ready handle. The cached opening path can instead reuse a stamped identity on that same handle. Cancelling drops the handle. Picco selects the ESP-IDF mbedTLS SHA-256 backend with hardware SHA enabled; the SDK acquires and releases the shared accelerator within each update. Host builds use RustCrypto. Hardware throughput and SD-read latency remain unmeasured.

Tests cover empty files, exact chunk boundaries, partial final chunks, EOF gating, repeated completion, computed IDs, and parsing through the same file handle after pathname replacement. The complete reader suite also checks ordinary document loading, staged EPUB validation, navigation, pagination, and typography through the shared opening path.


Library selection uses the configured cache root for a cancellable opening job. A warm hit goes directly to metadata and destination-chapter parsing; a miss hashes first. Page indexing then advances one page per poll. The ordinary uncached and parsed-document APIs remain available. [Cancellable library opening](picco-firmware.md#cancellable-library-opening) records result publication and cancellation behavior.

EPUB access seeks through the ZIP central directory and decompresses the requested chapter and its resources independently. Opening reads package metadata and navigation, then the destination chapter. Whole-book progress uses directory size metadata rather than decompressing other chapters. The current chapter retains a page index and one rendered-page layout; navigation temporarily keeps the destination alongside the current chapter for rollback. A regression counts reads across an archive with 8 MiB of unrelated padding and verifies that corrupt compressed data in an unrequested chapter does not prevent opening the first chapter.

## Cooperative startup

`ReaderStartup` owns the opening job, fonts, and saved state before a `Reader` exists. Its cached constructor opens the selected file and checks its stamp; archive parsing starts on the next poll. Cold opening hashes in five-millisecond batches before parsing. Metadata and chapter parsing remain synchronous. Indexing advances one page per poll. Dropping the job preserves reading state, although completed metadata validation can already have refreshed the disposable cache.

The simulator opens the explicitly selected book and loads cached library entries without a startup scan. Picco tries the most recently read cached book on cold boot and wake, followed by the default filenames and embedded specimen. Escape or device input can cancel opening. Rescan remains available even when the cache is absent. Font, state, and cache loading remain synchronous. [Device startup](picco-firmware.md#cooperative-startup-opening) records the device flow.

## Link previews

Selecting an entry in the shared Links on this page menu opens a temporary preview. The preview uses a separate chapter page index and one retained positioned page. It starts on the page containing the link target, including targets in supplemental XHTML documents outside the spine. Rendering uses the reader's fonts, typography controls, image resources, and display quantization. The header and footer remain available around the reduced content viewport.

Page buttons and taps in the left or right half of the content browse preview pages. The header, Back action, and Close footer return to the link list for menu previews or to the reading page for directly tapped note references. Neither return changes the reading position or back history. Select and the Follow link footer navigate to the previewed location and add the original reading position to back history. Direct taps on ordinary links start navigation without opening a preview. Cross-chapter navigation indexes one page per poll; same-chapter navigation uses the existing index. A link marked with an `epub:type` token of `noteref` or a `role` token of `doc-noteref` opens a preview. Preview state is temporary and is not saved or synchronized. Following a cross-chapter preview shares its parsed chapter with a pending navigation job. Cancel or Back restores the same preview page while its source book, position, and layout remain valid. If the reader changed during pending navigation, cancellation or a rejected completion discards the stale preview and shows an error in the root menu. The current reading state and history remain intact. Completion adds the return anchor once and releases the preview. [Cancellable chapter navigation](picco-firmware.md#cancellable-chapter-navigation) records cancellation, history, and memory behavior.

The controller rejects a preview after the source book, reading position, or layout changes. Failed target resolution and preview construction leave the current reading page available. Preview opening indexes one page per frontend poll. The page or link list stays visible meanwhile; Back abandons the preview. Cancellation and an external panel change discard the pending index. The controller validates the source book, position, and layout before each step and before completion. The first preview page is rendered successfully before the UI replaces the opening panel. The device suppresses automatic sleep during opening, and preview completion does not write reading state. Font-size shortcuts are ignored while a preview opens or remains visible; closing the preview restores access to those controls. Archive parsing, whole-paragraph work within a page step, and final rasterization remain synchronous. A page step is not a wall-clock deadline. The retained working set includes both source and destination chapters and page indexes. Physical latency and peak memory require qualification. Targets within a marked note body use a restricted preview; other targets permit browsing the containing chapter. Nested preview links and cooperative archive parsing remain unfinished.

Navigation tests cover unchanged source pixels and saved state, explicit follow/back behavior, invalid links, stale reflow, and supplemental notes. Tests also cover incomplete and stale opening jobs, cancellation through Back and Select, and external panel changes. UI tests cover close/follow controls and four-level rendering in portrait, landscape, and uneven viewport dimensions. The `device-menu` example writes `output/device-menu/link-preview.png` for visual inspection.

The styled EPUB event stream preserves note-reference semantics through inline style changes and linked images. Marker values use exact, case-sensitive tokens separated by ASCII whitespace. Attribute order does not affect recognition. A bare `type` attribute and substring matches do not mark a reference. Each marker attribute has a 4096-byte limit. The adapter uses the XML parser namespace resolver: the attribute must have local name `type` and namespace URI `http://www.idpf.org/2007/ops`. Inherited aliases and declarations on the link itself are accepted. Nested rebindings apply within their element scope and are restored after it closes. Undeclared prefixes, bindings to another URI, and unqualified `type` attributes do not mark a note reference. The same rule applies to the conventional `epub` prefix. Role recognition accepts the `doc-noteref` token. The parser does not infer notes from link text, superscript styling, destination IDs, or a CSS class. Tests cover alias inheritance, local rebinding, restoration after normal and empty elements, and incorrect or undeclared namespaces. The conventions follow the [EPUB notes guidance](https://idpf.github.io/a11y-guidelines/content/xhtml/notes.html) and [DPUB-ARIA note-reference role](https://www.w3.org/TR/dpub-aria-1.1/#doc-noteref).

The native X11 smoke test opens a marked note reference in the simulator, waits for the completed preview, closes it through the footer, and checks that saved position and bookmarks remain unchanged. It then reopens the preview, follows the note, and returns through back history. The simulator title identifies preview loading and the visible preview page. The test saves `output/simulator-smoke/note-preview.png`. This covers native pointer dispatch and event-loop completion; it does not measure physical touch or e-paper response.

## Semantic note bodies

The parser records complete note containers marked with EPUB `footnote` or `endnote` tokens, or ARIA `doc-footnote` or `doc-endnote` roles. EPUB attributes require the namespace URI `http://www.idpf.org/2007/ops`; aliases and scoped rebinding use the XML namespace resolver. Group tokens such as `footnotes` and `endnotes` do not mark individual bodies. Marker values are bounded to 4096 bytes. These conventions follow the [EPUB structural semantics vocabulary](https://www.w3.org/TR/epub-ssv-11/).

A note range starts at its first text or image content and ends at the closing container. Empty or unclosed containers produce no complete range. A preview whose target lies within a recorded range paginates only that body. Nested ranges select the innermost containing body. Inline note boundaries retain their original UTF-8 byte offsets and styles. Long notes retain cooperative pagination and page turning. Other links retain whole-chapter previews. Notes remain visible during ordinary reading; body extraction affects previews only. Semantic markers on image elements themselves do not currently create note containers. Images inside marked containers retain normal placement and resource resolution.

The preview page index and Follow share the full parsed source chapter. Source start and end boundaries limit note pagination and subsequent page reconstruction. Source block numbers and offsets remain unchanged. Follow therefore opens the full document, including content after the note; Back restores the reading origin. Notes bounded by whole paragraphs or images require no chapter or text copy. When a boundary lies inside a text paragraph, a page step temporarily copies that boundary paragraph and clips its style spans. Text before an inline note is replaced with neutral spaces in this temporary analysis buffer, with one byte of padding per original source byte. This prevents surrounding text from setting the note’s automatic direction, script context, or word boundary while preserving source offsets. Text after the note is excluded. The source chapter remains unchanged. The start boundary stays fixed while preview pages are reconstructed. Chapter parsing and paragraph analysis remain synchronous. Existing chapter input/event limits bound the source data but do not establish a Picco heap budget. Tests compare page boundaries and reconstructed pixels against an extracted-copy reference and verify that completed preview indexes retain the same chapter allocation. The `semantic-notes.epub` fixture checks adjacent and inline notes, whitespace before the first paragraph, long-note page traversal, incorrect namespace binding, source offsets, unchanged saved state, and cooperative Follow into the full document. Parser tests cover nested and empty containers, group tokens, aliases, and oversized attributes.

The `note-context.epub` fixture places a multi-page English note after Hebrew text and a multi-page Hebrew note after English text. Host tests compare every preview page with the same note rendered as isolated plain text, in both forward and backward traversal, with dictionary hyphenation disabled to remove metadata differences from the comparison. They also verify nonzero original byte offsets and Follow/Back locations. This covers automatic direction and script-context isolation for those fixtures, not general inline bidi override support or physical readability.

## Canonical library search

Library queries and candidate titles, authors, and displayed paths pass through NFC normalization, lowercase conversion, and NFC normalization again before substring matching. Final sigma (ς) is then matched as σ, because lowercase conversion writes a capital sigma either way depending on whether it ends a word, and a query may end inside a word of a title. Composed and decomposed accents and Hangul match across query and metadata representations. Matches retain the original entry and filesystem path. Metadata, content identifiers, stored positions, query text, and book bytes remain unchanged. Empty queries still return all entries in their existing order.

Completed scans order retained entries by the same canonical lowercase title key, in which ς and σ are therefore equal. Equal keys retain original-path order, independent of directory enumeration and cache hits. The implementation first sorts by path and then stably sorts by cached title keys; it does not clone paths into the title-key cache. Source metadata and filenames remain unchanged. This is Unicode string ordering, not language-specific collation. Accents remain significant, and truncated traversal can still retain a different subset if directory enumeration changes. The [canonical ordering regression](../tests/evidence/library-order-2026-11-08.json) checks uncached, cold-cache, and warm-cache scans, equal-title path ties, recreated files, original metadata/content, and canonical search results.

Accents remain significant. Compatibility characters, such as circled digits and presentation ligatures, remain distinct. Rust lowercase conversion does not supply full Unicode case folding or locale-specific casing; for example, STRASSE does not match Straße. Sigma is the only letter folded beyond lowercase. This behavior applies to shared local-library search, not OPDS queries sent to a server. The 64-byte UI query bound is applied to the original input. Normalization uses temporary strings during each scan of the indexed entries; it does not change the persistent cache format. Host tests cover title, author, path, case, accent, and compatibility behavior and selection of an original decomposed filename through the shared UI. Physical keyboard input and device memory/latency remain unqualified.

The [2026-11-08 search evidence](../tests/evidence/library-normalization-2026-11-08.json) records 59 targeted reader/UI tests, workspace Clippy, formatting, and an incremental monochrome Picco build. The firmware image grows from 4,999,808 to 5,121,104 bytes, an increase of 121,296 bytes including code, tables, and alignment. This is build evidence, not a physical memory or performance measurement.

## Source text selection

`selection::extract` reads a half-open range of chapter/block/byte locators from a document. Both endpoints must address text blocks at extended grapheme boundaries, including a paragraph's end. Reversed or empty ranges, missing blocks, endpoints inside UTF-8 characters or grapheme clusters, and image endpoints return errors. The caller must associate stored ranges with the exact document content ID; the extraction function does not accept or validate an external ID.

Selected text retains its parsed source bytes without normalization, visual bidi reordering, generated list markers, or layout-inserted hyphens. Nonempty text portions from different blocks or chapters are separated by two newlines. Images contribute neither alt text nor placeholders. A range containing no text fails. The API returns the complete string only after every included chapter and endpoint has been validated; a later parse failure does not expose a partial quote.

Extraction accepts at most eight chapters and 16 KiB of output including separators. It checks the chapter span before parsing and the output budget before appending. One parsed chapter is retained at a time. Chapter parsing remains synchronous and has the document parser's existing limits; the output bound is not a total heap bound. The [selection regression](../tests/evidence/selection-source-2026-11-08.json) covers Unicode grapheme boundaries, source preservation, block/chapter separators, image omission, missing endpoints, late errors, exact output limits, and chapter-work limits. Selection controls, clipping records, export, and highlight painting are described below. Dictionaries remain unimplemented.

## Saved clippings

`Clipping::capture` extracts a source range and records version 1, the exact book content ID, range, text, and caller-supplied timestamp. `validate_document` reopens the range against a supplied document, verifies its identity and grapheme endpoints, and compares the excerpt bytes. Stored-field validation alone does not establish that the range exists or the quote matches the book. Frontends must use capture for new records and document validation before using an imported record as a trusted source selection.

Each book state can retain at most 128 clippings. Each quote retains the selection module's 16 KiB text and eight-chapter limits. `ReaderState::add_clipping` rejects malformed fields, conflicting text for an existing range, and capacity overflow before changing state. Capturing the same range and text again returns false and preserves its original timestamp. Adding a clipping does not change reading position or recency. Duplicate ranges in loaded state are rejected.

Clippings use the existing host atomic state file and alternating device journal. Both validate clipping fields and the containing book identity before saving or accepting loaded state. Legacy book entries default to an empty list, and empty lists are omitted when serialized. The overall 4 MiB encoded-state limit still applies, including JSON escaping; the per-book capacity does not guarantee that every possible set fits that limit. The [clipping persistence regression](../tests/evidence/clipping-persistence-2026-11-08.json) checks both stores, malformed records, duplicate conflicts, count limits, exact-content verification, legacy defaults, and preservation of previous files after rejected saves. The shared reader menu supports page-text capture and excerpt viewing as described below. Highlight display and arbitrary-range selection gestures remain unfinished. Host JSON export is described below.

### Clipping menu

Clippings appears after the existing root-menu entries. Save page text captures the range from the first visible text line's source start through the last visible text line's source end. It excludes leading/trailing images and uses source extraction to omit intervening images, generated list markers, and layout-inserted hyphens. An image-only page or a range rejected by the selection limits reports an error without adding a record. Capture leaves the reading position and rendered book page unchanged. The timestamp uses the reader's logical recency counter rather than wall-clock time.

The panel lists saved quotes in capture order. Selecting an entry opens paged text rows, split at grapheme boundaries; these rows are an excerpt view, not the book's original typography or pagination. Back returns to the clipping list, then the This book menu, the root menu and reading. Repeated capture of the same source range and text retains the existing record. Ordinary frontend state persistence saves the updated list when leaving the menu. Capture does not imply that the state has already reached disk.

The [clipping menu regression](../tests/evidence/clipping-menu-2026-11-08.json) operates the shared button UI, verifies the exact visible source range and text, repeats capture, renders list/detail panels, returns to the same reading page, and saves/reloads the resulting state. The Picco build checks integration, and the existing native X11 reader/catalog/sync/tailnet smoke workflows pass with the appended menu entry. Native window input for clipping itself, physical input/display behavior, arbitrary text selection, and on-device export require further work.

### Deleting a clipping

The excerpt view starts with Delete excerpt. It opens a separate confirmation panel containing the captured quote, Keep excerpt as the initially selected action, and Delete this excerpt. Keep and Back return to the clipping list without changing state. Confirmation retains a copy of the record rather than a list index. It requires the same active book and an exact match of identity, range, text, timestamp, and version before removing one record. A missing or changed record rejects deletion; reordering alone does not retarget it. The confirmation is consumed after the attempt.

Deletion leaves reading position and recency unchanged and uses ordinary frontend persistence when leaving the menu. It does not remove the book, bookmarks, or sync checkpoint. The [deletion regression](../tests/evidence/clipping-delete-2026-11-08.json) checks the default Keep action, Back cancellation, successful confirmation, unchanged reading pixels/anchor, host and journal persistence, and refusal after record or active-book changes. Physical storage durability and native window interaction with this confirmation remain unqualified.

### Exporting clippings

`femto clippings-export BOOK --state STATE.json` writes a versioned JSON object to stdout. It includes the exact book content ID, title, author, and clipping records in saved order. Each record retains its version, range, text, and logical timestamp. A book without saved clippings produces an empty list. Missing host state uses the ordinary empty-state behavior and does not create a state file.

The command opens the supplied book and validates every stored quote against its source before writing the export header. A mismatched quote, invalid endpoint, malformed state, or failed book read returns an error without JSON output. Serialization streams to stdout after validation; an output I/O failure can leave partial output. Source verification is synchronous and can parse the same chapter for several excerpts. JSON escaping preserves Unicode source text and control characters without emitting terminal escape bytes literally.

On Unix, export holds the existing state-path lock and refuses a state file owned by another reader or sync process. It can create the normal lock sidecar but does not modify reading state. The [export regression](../tests/evidence/clipping-export-2026-11-08.json) invokes the CLI binary and checks exact Unicode records and metadata, unchanged state bytes, refusal of a forged second record before any output, empty exports, invalid inputs, and state-lock contention. The `--state` form accepts host JSON state. The `--journal` form reads a copied device journal as described below. On-device export controls and import are not implemented.

```sh
cargo run --locked -- clippings-export path/to/book.epub \
  --state path/to/reader-state.json > clippings.json
```

### Export from a copied device journal

`femto clippings-export BOOK --journal DIRECTORY` reads an offline copy of the Picco state directory containing `state0.bin` and/or `state1.bin`. Exactly one of `--state` and `--journal` is required. The directory must exist and contain at least one slot. The exporter does not create a journal, lock sidecar, or replacement slot. Use a copy taken while no writer is active; this command does not coordinate with running firmware or provide a live shared-storage snapshot.

The existing journal loader validates frame checksums, state schema, and generation ordering, rereads the selected winner, and rejects a changed winner. A torn newer slot can fall back to an older valid slot, so its export can omit more recent captures or retain excerpts deleted after that older save. If no slot is valid, export fails. The selected state's excerpts still undergo exact-source validation before output, just as with host JSON.

### Dictionary definition fields

Definition decoding validates each field before returning lookup results. Dynamic field identifiers must be ASCII letters. Non-final text fields require a NUL terminator, and binary fields require a complete big-endian length header and the declared payload. Length addition is checked before slicing. The last field in a declared type sequence consumes the remaining payload according to the StarDict encoding rule. A final text field accepts one optional trailing NUL for compatibility but rejects an embedded NUL followed by hidden data.

Lowercase text fields require valid UTF-8. Binary fields are skipped after framing validation and are not interpreted as text. Unknown text types remain skipped after UTF-8 validation. Legacy locale-encoded `l` fields are accepted only when their bytes are also valid UTF-8; no locale transcoder is provided. HTML, XDXF, Pango, and other markup reduction retains the existing backend behavior and does not become a complete validator for those languages.

Fields are decoded sequentially without retaining a vector of all field slices. The combined plain-text result is limited to 64 KiB, including separators and phonetic brackets. A malformed later field or excess decoded output fails the entire lookup; previously decoded text and earlier matching definitions are not returned as partial success. Temporary markup-conversion strings and the backend's per-lookup result vector remain separate allocations. This is not a whole-reader heap bound.

The regression covers declared and dynamic type sequences, phonetics, markup, binary fields before and after text, optional final text termination, missing separators, hidden suffix data, invalid UTF-8, truncated binary lengths and payloads, invalid field identifiers, overflowing binary lengths, and decoded-output expansion beyond the limit. Published WikDict samples and upstream tests are rerun with the change. Physical memory, latency, and legacy dictionary encodings remain unqualified.

### Prepared dictionary reuse

The shared UI retains at most one prepared dictionary after a successful lookup. Subsequent lookup moves that dictionary into the active job and performs lookup on the next poll without rebuilding indexes. Canceling an already prepared job returns it to the cache. Canceling incomplete preparation discards it. Ordinary reading and selection menu transitions retain the successful cache; changing configuration, including setting the same path again, discards it. Any error during a lookup drops the active dictionary, so a subsequent attempt opens and prepares a fresh one.

`ReaderUi::release_dictionary` drops active and cached dictionaries while preserving the configured path and pending source selection. Picco calls it after saving reading state and before storage sleep preparation. A failed sleep attempt therefore leaves dictionary lookup available but requires fresh preparation. Actual sleep and storage teardown remain physically unqualified.

The metadata file closes after opening. If both plain and compressed definitions exist, the unused compressed file closes as well. A retained dictionary holds the index and chosen definition file and, when present, the synonym file. The private index payload limits remain 128 KiB each; retaining them increases idle memory use. Dictzip tables, names, vectors, and file handles remain additional costs. The cache is memory-only and does not survive application restart or sleep. Source files must remain immutable while open; the cache does not detect same-size replacement or edits that still permit a successful read.

The shared UI regression uses a 1,000-entry dictionary to verify multiple preparation polls initially, one poll for repeated lookup, identical rendered results, preservation after canceling a prepared job, rebuilding after an injected read failure, explicit release, and same-path reconfiguration. Reading state remains unchanged. This establishes index reuse by poll behavior, not device latency or memory measurements.

### Dictionary chooser

The reader root menu includes Dictionary when at least one configured dictionary is available. The paged chooser displays filenames and marks the active choice with an asterisk. Selecting a row changes the dictionary, discards its previous prepared cache, and stores the selected filename in `ReaderState.dictionary_name`. Selection does not move the reading anchor or change book annotations. Existing state files without the new optional field retain automatic selection.

The simulator accepts `--dictionary-directory PATH` for discovery, mutually exclusive with `--dictionary FILE`. ## Pending work

Opening a book, moving to another chapter, reflowing, preparing a note preview, scanning the library and preparing a dictionary run in steps between input polls. The view that started the work stays on screen and no progress or cancel panel replaces it. Other input waits; Back abandons the work and leaves the view unchanged. ## Chapter page indexes

A chapter's page index always starts at the chapter's first page, so known page numbers never change. Opening a book, moving to another chapter and reflowing finish as soon as the page containing the target and the page after it are laid out; the remaining pages are indexed in bounded steps while the reader is idle, and a page turn past the indexed pages lays the next page out on demand. Until the index is complete the page count grows and the whole-book progress estimate uses the pages known so far.

A completed index is recorded under the index store directory, one file per book, keyed by the fonts' contents, the layout configuration and a caller-supplied salt. The Picco uses `/sdcard/femto/.index` and the firmware image hash as salt, so each firmware build starts with empty records; the simulator keeps them beside its state file and uses the path, size and modification time of its executable as salt, which differ after every rebuild. A recorded chapter opens by laying out only the target page, including a move to a previous chapter's last page. After recording the visible chapter the reader indexes and records the following chapter. A record is trusted only as far as layout reproduces it: every page taken from one is laid out from its recorded start and must end where the record says. When the target page does not reproduce, the record is ignored and the chapter is indexed afresh. When a later page turn, jump or prepared turn meets a page that does not reproduce, the index is replaced on the spot by one laid out from the chapter start through that page, which costs as much as opening the chapter there without a record; reading continues, and the fresh index replaces the record once it is complete. A target inside a chapter without a record still needs the pages before it laid out once.

Linked reads use the remaining chapter budget. These limits do not directly bound parsed-rule heap overhead. The EPUB parser has additional internal allocation paths that need auditing. The interactive reader retains parsed chapter text, a compact page-boundary index, and one positioned page. Library opening, UI font-size changes, device rotation, and cross-chapter contents/chapter/bookmark/link/preview-follow/back/page-turn navigation index one page per event-loop poll and support cancellation. Simulator and Picco startup hash and index cooperatively before constructing the reader and support cancellation without persistence. Picco tries the wake-resume candidate before default files and polls input/Wi-Fi between steps. Picco and simulator startup library traversal and file hashing also yield between scanner steps and can be skipped without replacing the metadata cache. Startup font/state loading, cache loading/saving, metadata/chapter parsing, synchronous controller actions, and sync preparation remain synchronous. Cross-chapter destination parsing remains synchronous. Bidi/hyphenation analysis still covers a whole paragraph. The eager pagination API used for exports and menus retains its separate 256-page and 131,072-total-glyph limits.

Images are limited to 2 MiB encoded data, 1,048,576 pixels and 8192 pixels per dimension, with at most 256 image events per chapter. Layout reads image headers; rendering decodes one placement at a time. Interlaced PNG requires an additional full color frame and progressive JPEG has decoder workspace, so the pixel limit does not represent peak heap use. PNG palette, alpha, 16-bit and Adam7 inputs and baseline/progressive JPEG have host fixtures. Animated PNG is rejected.

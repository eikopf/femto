# Remote input

`femto-remote` provides portable HID descriptor validation, BLE notification framing, keyboard and consumer-button decoding, press tracking, configurable page-turn bindings, and a bounded session queue. The shared reader has a `remote::RemoteControl` adapter. The optional Picco Bluetooth backend supplies notifications from one configured peer after HID discovery, Report Map/Reference validation, and subscription acknowledgements. Desktop Bluetooth input, on-screen peer selection, pairing, persistent bonds, settings-menu controls, automatic reconnect, and physical qualification remain unfinished.

## Picco discovery

`FEMTO_PICCO_BLUETOOTH=1 ./scripts/build-picco` enables the pinned ESP-IDF Bluedroid backend and writes separate artifacts under `output/picco-bluetooth`. It can be combined with `FEMTO_PICCO_GRAYSCALE=1`, which selects `output/picco-grayscale-bluetooth`. The build uses `sdkconfig.bluetooth` in addition to the base defaults, a separate generated SDK configuration, and a separate default target directory. The current image manifest records display levels and the image hash but does not identify Bluetooth features. The artifact directory and build evidence identify this variant.

When no peer file is present, an empty regular file at `/sdcard/femto/bluetooth-scan` requests one active ten-second legacy BLE scan on startup. If both files are absent, the Bluetooth driver remains uninitialized. A symlink, directory, or nonempty scan marker is rejected. The scan starts after successful asynchronous scan-parameter configuration. The reader's network polling path drives this transition and checks a fifteen-second deadline for configuration and scan completion. The deadline is observed when the reader polls; it does not interrupt synchronous font loading or rendering.

The HAL splits the modem into Wi-Fi and Bluetooth handles. GAP callbacks own an `Arc` of bounded shared state and retain no borrowed advertisement data. The callback copies validated data into a fixed inventory of 16 address/type pairs. Each entry retains at most 31 advertising bytes and 31 scan-response bytes. Repeated addresses update RSSI and supplied packets; empty packets preserve existing metadata. Additional addresses increment a saturating dropped-observation count without eviction. Invalid lengths and truncated advertising structures leave existing entries unchanged. UTF-8 names containing control characters are omitted from log output. A 16-bit HID service UUID is an advertisement hint, not authenticated identity or proof of a usable report map.

Completion logs address, address type, RSSI, optional name, and the HID-service hint. There is no on-screen chooser yet. Failure, completion, or sleep preparation releases the scanner. Shutdown marks callback state inactive, requests scan stop, unsubscribes, and releases the GAP and driver owners. No callback captures the driver, so the ownership graph has no callback/driver cycle. SDK destruction remains synchronous and can panic on SDK deinitialization failure; physical teardown timing and failure behavior remain unqualified.

The scanner does not connect, pair, or persist bonds. Its SDK defaults disable GATT-cache and bond writes to NVS; compile-time checks reject those options if enabled. The backend supplies no default NVS partition to the Bluetooth driver. Inventory limits exclude SDK controller buffers, caches, and allocations. Host inventory tests and a target build cannot establish radio operation, coexistence, power use, or teardown behavior on a Picco.

## HID service discovery

`/sdcard/femto/bluetooth-peer` selects one peer for a GATT connection at startup. It takes precedence over the scan marker. The file must be regular, at most 64 bytes, and contain an address type followed by a six-byte colon-separated hexadecimal address:

```text
public 12:34:56:78:9A:BC
```

`random` selects a random address instead of a public address. Hexadecimal case and surrounding ASCII whitespace are accepted. Extra fields, invalid UTF-8, malformed octets, and all-zero or all-ones addresses are rejected. An invalid peer file disables the Bluetooth service for that startup instead of falling back to scanning. This address selection does not authenticate a device. Address rotation and identity resolution are not implemented.

The platform registers one GATT client, makes a direct connection attempt, searches for HID UUID `0x1812`, and inspects the resulting characteristic cache. The SDK connection retry count is zero and its link-establishment timeout is ten seconds. The application checks a fifteen-second deadline for registration and each dispatched discovery operation when the reader polls. No automatic reconnect is implemented.

The portable `discovery::Discovery` state accepts only the expected phase, client interface, connection ID, and peer address. It retains at most one pending command and one primary HID service range. Duplicate or invalid HID services, absent services, operation failures, service changes, and disconnects invalidate pending work. Handles remain available for shutdown. SDK calls run outside the callback-state lock. Callbacks own their state through `Arc` and retain no borrowed event data or driver reference. This owner handles one attempt; it does not establish safe generation handling for a future reconnect loop.

Characteristic inspection first queries the count and rejects results outside 1 through 32. The SDK then fills a fixed caller-owned array at offset zero. A changed count is rejected. The portable `HidCharacteristics` validator requires distinct ascending value handles inside the service, one readable Report Map characteristic (`0x2A4B`), and one through eight Report characteristics (`0x2A4D`) with the Notify property. It returns the map handle and a fixed array of input candidates. These checks cover characteristic metadata; they do not validate a Report Map or associate Report References with notification handles.

After characteristic inspection, the backend queries each input candidate's descriptors with a count check and a fixed 16-entry buffer. The SDK query selects descriptors owned by that characteristic. The portable `ReportDescriptors` validator requires ascending distinct handles after the value handle and before the next characteristic value, or within the service end for its last characteristic. Exactly one Report Reference (`0x2908`) and one Client Characteristic Configuration (`0x2902`) descriptor are required. A changed count, missing descriptor, duplicate descriptor, or invalid handle range rejects the service.

The backend reads the Report Map, then each candidate's Report Reference, with one outstanding read and a fifteen-second deadline per operation. The fixed `ReadSlot` copies the completed SDK value before the callback returns. Read kind, client interface, connection ID, and handle must match the pending operation. Other connections cannot complete it. Unexpected handles, duplicate completions, failed status, empty maps, oversized maps, and references whose length is not exactly two bytes invalidate the read. Disconnect, service change, timeout, or shutdown discards pending and completed values. HID parsing runs in the reader loop outside the callback-state lock.

This BLE profile accepts Report Maps of at most 512 bytes. The pinned [ESP-IDF read handler](https://github.com/espressif/esp-idf/blob/v5.5.2/components/bt/host/bluedroid/stack/gatt/gatt_cl.c) assembles long reads but can truncate a larger value at `GATT_MAX_ATTR_LEN` and report success. The inspected SDK sets that limit to 517 bytes. The backend rejects results above 512 bytes and checks at compile time that the public SDK attribute limit exceeds its own bound. The portable HID parser retains its separate 4,096-byte limit. The SDK source inspection is not a physical long-read interoperability test.

After parsing the map, the backend requires each notifying candidate's reference to have input type 1. `ReportRoutes` requires each declared input report ID exactly once across the discovered characteristics. The subscription state machine registers each value handle for notifications, waits for its acknowledgement, writes `[1, 0]` to its Client Characteristic Configuration descriptor, and waits for the write acknowledgement. Input remains disabled until all routes complete. The SDK notification-registration capacity is eight. Failed, duplicate, or out-of-order acknowledgements invalidate the session.

Notifications require the configured peer address, client interface, connection ID, and a validated value handle. Input is ignored until the main reader loop is ready. Accepted notifications enter the fixed session queue. The reader authorizes an action under the callback-state mutex, then releases the mutex before rendering. A later disconnect discards queued input but cannot retract an already-authorized action. Local button events take priority. Remote turns use the existing navigation, idle activity, redraw, and position-saving path. Menus consume presses without changing their selection.

Errors, timeouts, disconnects, service changes, and sleep preparation invalidate queued input and release the connection. Shutdown unregisters notifications before closing and releasing the client and driver. SDK destruction remains synchronous and can panic on an SDK error. Reads and configuration writes use `GattAuthReq::None`; peers requiring authentication remain unsupported. No pairing, bond storage, or automatic reconnect is implemented. Physical connection, notification, long-read, and teardown behavior remain unqualified.

## Parser and limits

The crate pins `hidreport` 0.6.0 with default features disabled. The vendored MIT-licensed source retains its copyright notice. Its local patch makes HID Push/Pop save and restore only global state. A regression demonstrates that local usages remain available until the next main item. The original source restored local usages as well. The pinned archive and evaluation findings are recorded in [dependency decisions](dependencies.md#hid-remote-input).

Private preflight checks run before semantic parsing. Limits are 4,096 descriptor bytes, 256 items, eight global-stack entries, eight collection levels, eight report IDs, 256 declared fields across report types, 32 bits per field, 512 data bits per report type and ID, 32 local items between main items, and 256 entries in a usage range. Unsupported long or reserved items, delimiters, invalid stack operations, incomplete collections, mixed numbered/unnumbered reports, and missing usage pages are rejected. Four-byte usage minimum/maximum items are rejected because the parser applies the global usage page to those ranges. Individual four-byte usages retain their explicit page and are supported. These are input and work limits; they do not establish measured Picco heap usage.

The parser's raw report lookup and extraction APIs can panic on empty or truncated input. They are not exposed through the crate API. The private framing adapter requires an exact two-byte BLE Report Reference with input type 1, a declared report ID, a nonempty payload of at most 64 bytes, and an exact framed report length. Numbered notifications receive their report-ID prefix in a fixed 65-byte buffer. Unnumbered notifications retain their payload and require reference ID zero.

## Presses and bindings

`RemoteInput::new` validates and parses one report map. `accept` takes the Report Reference and notification payload, then returns newly pressed HID usages. The caller must associate the characteristic and reference with the correct report map. The decoder supports absolute keyboard and consumer-button variables with logical range 0 through 1, and unsigned arrays whose values select declared usages. Unsupported usage pages are ignored. Signed arrays and non-button variables on supported pages are rejected.

Held state spans at most eight input report IDs and 32 unique usages. Duplicate array slots and usages shared by different report IDs produce one press. Repeated held reports produce none. Releasing and pressing again produces a new press. Keyboard rollover/error codes, invalid values, invalid framing, and per-report or combined capacity failures preserve all previous state. `reset` clears held state without emitting events; the next held notification is treated as a fresh press. No hold-repeat timer is implemented.

`Bindings::default` maps keyboard PageUp and LeftArrow to Previous, and PageDown and RightArrow to Next. `Bindings::new` accepts up to 16 keyboard or consumer usage mappings. An empty list disables page turns. Duplicate usages, unsupported pages, zero usages, and reserved keyboard error usages are rejected. Consumer volume mappings require explicit configuration. New presses in one notification coalesce to one action when their directions agree; opposing new presses produce none. Separate notifications are not combined into a chord window. Reader state persists custom mappings in the optional `remote_bindings` field. Each entry has a numeric 32-bit HID `usage` and an `action` of `previous` or `next`. The list replaces the default map. Missing or null settings use defaults; an empty list disables remote page turns. Decoding uses a fixed 16-entry array and rejects the seventeenth entry, duplicate or invalid usages, unknown actions, and unknown entry fields. Host state files and device journals retain the same representation. No settings-menu editor is implemented.

## Session queue

`inbox::Inbox` contains a fixed FIFO of 16 notifications with at most 64 payload bytes each. `begin` discards queued input, emits a session-reset event, and returns a monotonically increasing token. Callbacks must retain that token. Old-token input and disconnect callbacks do not change a newer session. Token exhaustion invalidates the session instead of reusing a token.

Queue overflow, invalid notification framing, and current-session disconnect discard all queued input, invalidate the token, and emit a reset event before any further input. Overflow and framing faults require a new session. The consumer must clear held decoder state on reset. Delivered notifications retain their token so the consumer can recheck `is_current` before action dispatch.

The platform must serialize callback access, queue polling, and action authorization. The queue has no internal mutex. A token check alone does not synchronize a concurrent disconnect with dispatch. The callback storage and queue must outlive all callbacks that reference them; generation checks do not make dangling callback pointers safe. A threaded reader test verifies that rendering can proceed after releasing the authorization lock while a disconnect discards pending input. SDK callback lifecycle behavior remains physically unqualified.

## Reader adapter

`gatt::ReportRoutes` validates the input characteristics discovered in one HID service against its parsed report map. It stores at most eight routes in a fixed array. Each declared input report ID requires exactly one route. Unknown or duplicate IDs, non-input references, zero value handles, configuration descriptors preceding their value handles, and overlapping handles are rejected. Notification lookup uses the characteristic value handle; configuration descriptor handles cannot supply input. The transport remains responsible for checking UUIDs, notification properties, service membership, descriptor ownership, and successful notification subscription. This table does not authenticate a peer or establish a BLE connection.

`RemoteControl::connect_gatt` installs the validated map and routes together. Invalid replacements preserve the current session. `submit_gatt` resolves a characteristic handle only after checking the session token. An unknown handle in the current session invalidates input and discards queued turns. Old-session callbacks cannot invalidate or supply input to a newer connection, even when the platform reuses characteristic handles. The platform must attach the correct generation to each callback; a token created from a reused connection ID alone is insufficient. The existing serialization and callback-lifetime requirements still apply. Raw `connect` replaces and clears GATT routes.

`femto_reader::remote::RemoteControl` owns the decoder and session queue. Each notification resolves actions from the current `ReaderState.remote_bindings`; changing a mapping does not replay a held press. `connect` validates a report map before replacing the existing session and returns its callback token; it does not establish a radio connection. Invalid replacement descriptors preserve the current session. The caller submits notifications with the token and polls one event at a time from the reader loop.

`poll_action` returns an authorized action for rendering after the caller releases its lock. `poll` also applies that action through the shared UI. Both process reset and notification events under the same serialization as callback submission and disconnect. It checks the token before decoding and dispatching an action. A decode error invalidates the session and discards queued input. Disconnect and overflow likewise prevent queued turns. The returned error can be reported by the frontend without changing the reading anchor.

Page turns are dispatched only when no reader panel is open. Menus, previews, dictionary panels, reflow, and navigation panels consume presses without moving menu selection or the book. Held state still advances, so closing a panel does not replay a consumed press. A release and new press are required. Accepted turns use `ReaderUi::turn` and its cooperative navigation path; chapter transitions retain cancellation and source-position behavior.

Shared integration tests drive actual HID notifications through the queue, decoder, bindings, and reader. They cover held suppression, Previous restoring exact page pixels, unchanged menu selection, reflow gating, cross-chapter cancellation and completion, stale sessions, queue overflow, decode errors, and invalid replacement maps. The Picco event loop supplies notifications through this adapter; desktop Bluetooth input remains unfinished.

## Validation

The workspace gate includes 48 portable-crate tests and 18 upstream parser library tests. Coverage includes descriptor framing and bounds, global/local state separation, 1,621 accepted single-byte descriptor mutations without parser panic, keyboard arrays, numbered consumer reports, release/repress behavior, report-ID deduplication, atomic rejection at held-key limits, binding conflicts, FIFO order, old-session suppression, overflow, disconnect, and token exhaustion. The isolated evaluation also passes debug and release tests. The pinned Xtensa toolchain passes `cargo check` for `femto-remote` with target `xtensa-esp32s3-espidf`, `espidf_time64`, and `build-std=std,panic_abort`. This checks the portable crate without linking or executing Picco firmware. The monochrome firmware also builds with the reader adapter and dependency, including transport callbacks and runtime remote dispatch in the Bluetooth variant. The upstream external descriptor corpus, broader fuzzing, and actual BLE devices remain unqualified.

Target compilation can be repeated from the repository root:

```sh
MCU=esp32s3 RUSTFLAGS='--cfg espidf_time64' nix-shell nix/firmware.nix --run 'cargo check --locked -p femto-remote --target xtensa-esp32s3-espidf -Z build-std=std,panic_abort'
```

A custom map can reverse PageDown by storing this field in reader state:

```json
{"remote_bindings": [{"usage": 458830, "action": "previous"}]}
```

Applications construct validated maps with `SavedBindings::new` and assign them to `ReaderState.remote_bindings`. The private entries cannot be mutated into an invalid configuration after construction. Legacy state without this field remains compatible.

The initial link failure under default BLE 5 features is retained alongside the successful build with explicit legacy scan support. No physical radio test is recorded.

The seven added tests cover peer parsing, discovery transitions, cancellation of pending work, service validation, and characteristic bounds. Tests cover read ownership and bounds, descriptor ranges, cancellation after completion, and a map/reference sequence that produces a decoded PageDown press. SDK source hashes record the long-read and authentication-path inspection. Physical long-read and page-turner operation remain unqualified.

Subscription tests cover all-route acknowledgements, the eight-route boundary, unexpected callbacks, failures, and cancellation. A threaded reader test covers action authorization before unlock and discarded pending input after disconnect. Physical Bluetooth operation remains unqualified.

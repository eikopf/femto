# TCP engine

`femto_microlink::tcp::Stream` provides one outbound IPv4 TCP flow using smoltcp 0.12.0. Each stream has 16 KiB application receive and send buffers. Each packet queue holds at most eight packets of the tunnel MTU. The engine does not create OS sockets, bind a host interface, or require a privileged TUN device. There is no public listener API. Tests use a private listener to exercise the wire protocol.

The caller supplies distinct local and remote IPv4 addresses, nonzero ports, and a random seed for sequence generation. Production callers must obtain an unpredictable seed from the platform RNG. `poll` accepts monotonically increasing milliseconds relative to stream creation, starting at zero. Backward and overflowing times return an error. The socket timeout is 30 seconds; callers must also enforce the application operation's deadline and cancellation.

`write` and `read` copy partial application data. A zero count can indicate backpressure or no currently buffered data. `state` exposes the TCP state for connection and EOF handling. `close` queues an orderly transmit shutdown. `abort` makes buffered data inaccessible, clears packet queues, and rejects later reads, writes, ingress, and polls. Aborting does not send an RST. The caller drops the engine to release allocations.

`ingest` accepts only checksummed, unfragmented IPv4 TCP packets for the exact configured endpoint pair. IPv4 options, wrong addresses or ports, malformed lengths, invalid TCP checksums, and packets larger than the tunnel MTU are rejected. A full ingress queue returns a capacity error. Egress queue saturation withholds smoltcp transmit tokens and resumes when the caller drains packets. The caller retrieves packets through `take_packet` and submits them to the authenticated network owner. Dropping a retrieved packet permits ordinary TCP retransmission; it does not imply delivery.

## Network ownership

`Network::connect_tcp` allocates one of four outbound flows on the assigned local IPv4 address. The destination must belong to the authenticated peer directory. The owner obtains a random sequence seed through `getrandom`. Local ports advance from 49152 through 65535 without reuse during that owner's lifetime, including across disconnects. Exhaustion returns a capacity error. Opaque handles include a unique allocation identity, so a handle from another owner or a removed flow cannot access a new connection.

The caller alternates `poll_tcp` with the existing network transport pump. It uses `tcp_state`, `write_tcp`, and `read_tcp` for connection and application progress. `poll_tcp` starts or waits for the existing paced WireGuard handshake, releases matching authenticated incoming packets, advances the stream, and queues at most eight outgoing packets per call. The shared ciphertext queue applies backpressure before packets leave the engine. An error after packet extraction can drop that packet; TCP retransmission handles loss while the caller retains operation-level deadline and cancellation responsibility. Polling only a flow does not drive host UDP, DERP workers, or coordinator ingestion.

Each flow retains a coordinator-generation permit. Every application access checks the permit and peer expiry. The data plane tracks a separate authorization identity derived from the peer authorization records and compiled receive-policy groups. Map updates preserve that identity only when both remain structurally equal. In that case, the network owner refreshes managed TCP permits inside the map-application boundary and restores reply permissions for flows that already queued outbound traffic. TCP state and unread application data survive keep-alives, identical policy updates, and route-only changes. Unsynchronized state, peer-key/address/expiry changes, different compiled policy groups, and malformed updates invalidate flows. The comparison is conservative: reordered equivalent rules or a change to an unrelated peer can still close all flows. Per-peer selective continuity remains unfinished. Disconnect and clock rollback clear all flows. Outgoing ciphertext and retained delivery permits carry the opaque flow handle. `abort_tcp` removes the flow and its queued ciphertext, and later delivery validation rejects retained permits. `close_tcp` begins orderly shutdown and retains the slot; the caller must eventually call `abort_tcp` to release it.

Managed outbound flows install exact-tuple reply permission after the owner queues encrypted outbound traffic. The bounded table contains at most four entries. Each entry binds the authenticated peer key, local address and port, remote address and port, and a weak lease owned only by the connection. Reply admission requires valid IPv4 and TCP checksums and an ACK or RST; bare SYN and SYN+RST are rejected. The existing packet parser rejects fragments and IPv4 options. Peer-address ownership and key expiry remain mandatory. Smoltcp checks TCP sequence and acknowledgment validity after admission.

The same reply permission is checked when an authenticated packet is released from the input queue. Removing the connection drops its lease, so retained packets cannot use its reply permission. The owner also drops the lease when polling reaches the Closed state. Map application clears the table before the network owner conditionally restores managed reply permissions under unchanged authorization. Disconnect clears it without restoration. Holding an application socket handle does not keep a lease alive. Ordinary static receive rules remain an independent source of permission. Raw `send_ip` calls do not install reply permission, and UDP return tracking remains unchanged. This supports replies to managed outbound connections without an ephemeral-port receive rule; it does not establish complete Tailscale connection-tracking compatibility. A verified host TLS adapter uses these APIs. The optional catalog library adapter selects these streams; the host enrollment command can fetch one catalog; device OPDS integration remains unfinished. Per-owner stream bounds are implemented; applications that create several network owners must bound that aggregate separately.

Host tests cover a dropped SYN, a dropped data segment, exact ordered transfer after retransmission, partial writes at the send-buffer limit, response data before FIN, connection timeout, ingress capacity, wrong-direction packets, clock rejection, and cancellation with unread data. The test peers use the same smoltcp version. These tests do not establish interoperability with an independent TCP implementation, a live tailnet, or the Picco. The Picco firmware compiles femto-microlink and its application driver; device OPDS can route selected HTTP origins through the shared driver.

The opt-in [Headscale fixture](headscale-qualification.md) independently qualifies separate direct and relay-only IPv4 TCP flows against official Tailscale 1.104.5. Its input policy permits only the femto address to reach the peer service port, without a reverse ephemeral-port rule. The check verifies 64 KiB in each direction over at least 195 seconds, at least two authenticated WireGuard handshake responses, remote EOF after the complete response, client EOF at the server, and the final Closed state. Each TCP connection remains usable after renewal and beyond the original transport keys' expiry. The relay-only probe creates no UDP transport and counts authenticated responses received through the DERP pool. The independent peer runs in userspace with private temporary state. This check does not qualify the blocking adapter, TLS/HTTP, deliberate loss, simultaneous flows, relay failover, NAT traversal, or physical Picco behavior.

Network-owner tests transfer a request and response through authenticated WireGuard sessions using the relay routing path in memory. They check partial response reads, revocation with unread data, retained delivery invalidation after a map update and explicit abort, four-flow capacity, cross-owner handle rejection, source-port non-reuse, destination ownership, and disconnect. The client has no inbound policy rules and the server permits only TCP port 80. Additional tests reject wrong ports, unsolicited SYNs, SYN+RST, and bad checksums, and reject queued replies after lease removal, map replacement, or peer expiry. The tests do not open a live DERP connection.

## Host application I/O

`application_tcp::Stream`, also exported as `host_tcp::Stream` for compatibility, implements blocking `std::io::Read` and `Write` over a caller-supplied driver. Connection setup resolves an authenticated peer name and polls the managed TCP flow until established. One absolute deadline covers name resolution, WireGuard setup, TCP setup, and every subsequent operation. An atomic cancellation flag is checked at operation and pump boundaries. Pending reads and writes poll transports and wait up to one millisecond before retrying. A temporary empty receive buffer produces WouldBlock internally; received FIN produces EOF after buffered data has been read. Reads stage at most 1024 bytes and copy them to the caller only after the final deadline/cancellation check succeeds. Partial writes preserve ordinary `Write` semantics. `flush` checks the operation boundary but does not wait for acknowledgment or independently pump queued data.

The driver provides serialized network access and a bounded transport pump. It must preserve the kind of `network::Error::Io` so the stream can distinguish backpressure from terminal failure. `NetworkDriver` implements this contract with `ControlledNetwork::run` and the existing host UDP/DERP pool pump. The caller supplies the authenticated owner, UDP transport, configured relay pool, and clock. Relay connection creation, endpoint publication, and coordinator reconnection remain the caller's responsibility. A blocking custom driver can violate the stream's deadline bound; the adapter cannot interrupt arbitrary driver code.

Cancellation, timeout, a terminal I/O failure, and stream drop remove the managed TCP flow. Connection setup failures also drop the partially created stream. The adapter owns its driver. `Shared::new(driver)` provides a cloneable single-thread owner for successive or interleaved streams. Each stream retains independent deadline and cancellation state. Dropping a stream removes its flow but preserves the shared runtime until its last owner is dropped. The same runtime retains the coordinator, WireGuard sessions, UDP socket, and relay pool. Creating a stream with an unshared owned `NetworkDriver` still closes that runtime on drop.

Shared operations use exclusive `RefCell` borrows and return WouldBlock for reentrant access. Cancellation during an existing operation queues cleanup in a separate list bounded to four handles. Cleanup runs after that operation and before later network work. Duplicate handles are coalesced. Cleanup of a flow already invalidated by the network owner succeeds. This is a single-thread adapter; it does not introduce a background packet pump or concurrent application execution. The TLS-over-tailnet adapter uses this stream. The optional `femto-catalog/tailnet` feature provides the catalog `Transport` implementation.

Host tests run an HTTP-style request and complete response through the blocking adapter and in-memory encrypted network owners. `read_to_string` verifies response bytes followed by orderly EOF. Other tests stall the WireGuard handshake and verify slot cleanup on cancellation, absolute timeout, and transport-pump failure. These are application-I/O tests; they do not constitute an OPDS acquisition or an independent live-server test.

The shared-runtime test performs two successive encrypted HTTP-style exchanges from worker threads through ThreadShared, cancels and drops each stream, and verifies that the runtime survives until its final owner is dropped. It also cancels one flow inside a serialized network operation, verifies cleanup afterward, and checks that a sibling flow remains accessible.


`ThreadShared` provides a mutex-backed alternative for Send drivers. Runtime lock contention returns WouldBlock and the stream retries under its deadline, including during connection setup and buffered-plaintext authorization. Poisoning fails closed. A separate four-handle abort queue handles stream destruction during a serialized operation. The Picco runtime implements the Driver contract; the reader manager and catalog worker share this owner for selected HTTP origins. Tests cover contention through timeout, poisoned locks, and cancellation after a successful read without changing the caller's buffer.

## TLS over tailnet TCP

`host_tcp_tls::Connector` wraps the managed host stream with pinned rustls 0.23.46. The default connector uses the pinned Mozilla root set. A custom-root constructor supports private certificate authorities while preserving chain, validity, and hostname verification. The authenticated peer name is also the TLS server name. The connector does not expose certificate-verification bypasses or relay certificate-pin overrides. It advertises HTTP/1.1 through ALPN, disables session resumption, and sets rustls's outgoing buffer limit to 16 KiB. The underlying stream's absolute deadline and cancellation apply during TLS setup and application I/O.

Every TLS operation rechecks the managed flow's authorization before and after accessing rustls. Reads stage at most 16 KiB of plaintext and copy it to the caller only after the final check succeeds. This covers records already decrypted before a coordinator update. A terminal TLS or authorization error drops the underlying stream and releases its slot. Dropping the TLS wrapper aborts the managed flow; it does not attempt a blocking close-notify exchange. Clean peer close-notify produces EOF after buffered plaintext, while a truncated TLS stream remains an error.

Tests run rustls client and server connections through in-memory WireGuard and TCP owners. They cover valid, wrong-name, expired, and untrusted certificates; complete payload and close-notify; truncated TLS; and cancellation or map invalidation with plaintext still buffered inside rustls. Failed authorization leaves the caller's read buffer unchanged. These tests use local certificates and the same TLS implementation at both ends. The [Headscale fixture](headscale-qualification.md) separately exercises the production blocking TCP and host TLS adapters against Python's OpenSSL-backed server behind official Tailscale 1.104.5. It checks a 64 KiB HTTP response, HTTP/1.1 ALPN, certificate-name and issuer rejection, clean close-notify, and refusal of a complete response with truncated TLS shutdown over both direct and relay-only connections. The relay-only fixture creates no UDP socket and requires incoming DERP events. This uses private fixture trust roots and a destination-port-only input policy. The TLS-specific phase checks an exact raw HTTP exchange. The application phase qualifies the catalog HTTP parser and authenticated EPUB acquisition through the library tailnet transport on both direct and relay-only paths. On both paths, the application phase also checks the portable progress exchange, conditional-write conflict handling, and reader-journal persistence. Complete CLI/device sync workflows, physical device TLS, and relay migration/failover remain unqualified through this path. The device uses a separate compiled Mbed TLS callback adapter described in [device networking](device-network.md#https-over-managed-tailnet-tcp). Its injected ABI tests check ownership and error handling; `scripts/check-native-tls` additionally exercises the actual Rust adapter with host Mbed TLS and an OpenSSL server over loopback OS TCP. That fixture does not use the managed WireGuard/TCP path or the ESP certificate bundle.


The general packet and route-plan generation still changes on every map application. Pending handshakes, raw queued plaintext, queued ciphertext, retained transport-delivery permits, and relay plans therefore retain their existing stale-generation behavior. The TCP engine retains unacknowledged application bytes and retransmits packets discarded by an update. This avoids carrying old route metadata into a new map, but frequent maps can add retransmission delay and relay reconnection work. The update preserves managed application streams rather than all transport queues.

Continuity tests retain unread TCP data across a keep-alive, an identical empty policy, and a peer endpoint patch. A subsequent encrypted response verifies restored reply permission. A changed policy still invalidates unread data and retained delivery. A separate test ensures an unsent connection does not gain reply permission during refresh. TLS tests read buffered plaintext after a keep-alive and reject it after peer removal. Authorization-identity tests distinguish identical policy from expiry changes and malformed updates. Physical-device and live enrolled continuity remain unverified.

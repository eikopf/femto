# Dependency decisions

Cargo.lock pins the resolved dependency graph. flake.lock pins the host development environment. Rust dependencies have been built and tested on the host; ESP-IDF compatibility remains a separate build gate.

## Reader

`unicode-normalization` 0.1.26 supplies canonical normalization for library search. The [pinned iterator API](https://docs.rs/unicode-normalization/0.1.26/unicode_normalization/) and downloaded source were inspected before use. Default features are disabled; its `no_std` implementation uses `alloc` through `tinyvec` 1.13.3. Both lockfiles pin these additions. Its Rust 1.36 minimum fits the toolchain, and its tables report Unicode 18.0.0. The package license is `(MIT OR Apache-2.0) AND Unicode-3.0`; the Unicode data notice is retained in [Unicode normalization notices](licenses/unicode-normalization-data.txt). Search normalizes to NFC, applies Rust lowercase conversion, and normalizes again. No normalization code or Unicode table is reimplemented locally. This is canonical substring matching, not full Unicode case folding, compatibility matching, collation, or accent removal. The transformation allocates temporary strings per candidate field and does not retain a second metadata index. Device latency and peak heap use remain unmeasured.

Local image-style patches carry non-inherited CSS `width`, `height`, `max-width`, and `max-height` through styled image events. The reader resolves pixel and percentage values against its page content area. Automatic dimensions preserve intrinsic proportions; two specified axes can change them. The existing grayscale resampler handles both enlargement and reduction. Page and resize-buffer bounds remain enforced; [image sizing](typography.md#image-size-limits) records the supported subset.

`epub-stream` 0.1.0 provides ZIP, OPF, navigation, XHTML, and a CSS subset. Femto consumes its styled chapter events and owns the page composition and source locators. Its convenience layout engine is not used because the reader needs shaping and bidi-aware line layout.

The crate is vendored under `vendor/epub-stream` with its MIT license. The published crate archive has SHA-256 `60d1fda120a11d9725ce091ac2e3c8be7d95294a594f0d3670daba342e05c432`. The vendor manifest retains runtime dependencies and omits upstream development tooling and binary targets. A local patch in `render_prep.rs` preserves whitespace at XML text-node boundaries and does not collapse non-breaking spaces. The unpatched normalizer removed spaces around inline elements. Femto's EPUB fixture checks the resulting sentence across bold and italic runs. The older tokenizer API has separate whitespace behavior and is not used by Femto's document path.

The whitespace patch resolves inherited CSS `white-space` before emitting runs. Normal and nowrap collapse spaces and segment breaks; pre and pre-wrap preserve them; pre-line preserves breaks while collapsing spaces. Inherit and unset resolve against the parent; initial resolves to normal. The `pre` element supplies a preservation default that author CSS can override. Inline code, kbd, and samp no longer imply preservation. A stream normalizer shares collapse state across styled runs, entities, and CDATA, retains nonbreaking spaces, and normalizes CR/CRLF breaks. Structural events reset the state. Pre elements emit paragraph boundaries. The whitespace fixture checks text, blank lines within a pre block, links, and source locations through pagination.

This patch supplies whitespace parsing, not full CSS preformatted layout. Femto still wraps pre and nowrap text to its viewport, trims trailing line spaces, and uses the selected proportional font. Whitespace-only blocks are discarded. Leading block spaces and the first newline after a pre start are not removed by HTML-specific rules. CSS break-spaces and newer whitespace longhands are unsupported. These limits remain separate from the [CSS Text whitespace rules](https://www.w3.org/TR/css-text-3/#white-space-property).

A second render-preparation patch emits element anchors and hyperlink start/end events, which the published event API drops. Navigation attributes are XML-unescaped and capped at 4096 bytes. Anchor events follow structural start events so block boundaries remain correct. The trace adapter and its upstream match test account for the new variants. Femto maps these events to source locations and link ranges; navigation does not reparse text with an independent tokenizer. [Navigation behavior](navigation.md) records URI resolution and current limits.

The resource-event extension shares the styled chapter event path with manifest-declared XHTML documents outside the spine. It reads XHTML with the same hard byte cap and resolves stylesheets and images against the resource path. Femto assigns stable supplemental indices and keeps normal spine navigation separate.

A further render-preparation patch carries inherited XHTML `lang`/`xml:lang` declarations through `StyledRun`. Explicit empty values clear inheritance, and XML language takes precedence on the same element. Femto stores the resulting language on source spans, supplies book metadata as the undeclared default, and passes each span's language to Rustybuzz. The host fixtures exercise parser inheritance and the resulting hyphenation and localized glyph selection.

The vendored CSS parser and computed styles also carry `hyphens` declarations. Per-element inheritance resolves `inherit` and `unset` against the parent after stylesheet and inline overrides; `initial` resolves to manual. Femto translates the resolved policy into its own copyable text style, then controls dictionary candidates and soft-hyphen visibility during pagination. Unsupported broader CSS cascade features remain outside this patch. Adjacent source runs with equal style and language merge in Femto's paragraph builder, preserving shaping across numeric entities without altering source offsets.

The ZIP reader retains at most 256 central-directory entries in a heap vector. The original inline array produced large stack frames while opening EPUBs on the 64 KiB catalog worker. The patch preserves the entry limit and uses the inflater's boxed constructor. The routine checks run the complete vendored library test suite, including ZIP and book APIs. The published crate omits the books referenced by 26 upstream tests. Those tests now use original `book-api.epub` and `book-api-legacy-cover.epub` fixtures generated by `scripts/make-fixtures.py`, with their behavioral assertions retained. The tests use distinct local fixture names and do not claim coverage of the omitted accessibility or Frankenstein corpus. The local books exercise navigation, streamed resources and size caps, stylesheet loading, embedded-font discovery, cover selection, and render preparation. Additional assertions require nonempty stylesheet/font results and exact cover bytes. The two cover paths use EPUB 3 manifest properties and EPUB 2 metadata with NCX navigation. The embedded DejaVu Serif face retains its license inside each archive. Femto's reader fixtures also run in the workspace suite.

`miniz_oxide` 0.9.1 is vendored under `vendor/miniz_oxide` with its MIT, Zlib, and Apache-2.0 licenses. The published archive has SHA-256 `b63fbc4a50860e98e7b2aa7804ded1db5cbc3aff9193adaff57a6931bf7c4b4c`. With `with-alloc`, a local patch allocates the 32 KiB inflate dictionary, decompressor, and three Huffman tables on the heap without constructing the complete state on the stack. Fixed dimensions and decoding behavior remain unchanged. Builds without `with-alloc` retain inline storage. The patch uses safe Rust and retains the crate's unsafe-code prohibition. EPUB and PNG consumers share this version. Host upstream tests and a 64 KiB worker acquisition fixture exercise the patch; physical memory qualification remains open.

The CSS and render-preparation patches retain containing-block text alignment through styled runs. Left, center, right, start, end, and justify reach Femto's paragraph layout. Inherit and unset resolve against the parent; initial resolves to start. Inline declarations do not change the containing block's alignment. Logical start/end use each bidi paragraph's declared or detected base direction. Alignment translates positioned glyphs after line breaking without changing clusters, advances, or source locators. Justification expands internal U+0020 space clusters in visual order after shaping. Final lines, explicit hard breaks, and lines without eligible spaces retain start alignment. Nonbreaking spaces do not expand. Glyph IDs, clusters, source positions, and line breaks remain unchanged. The algorithm does not insert Arabic kashida, distribute spacing between CJK characters, reshape glyphs, or optimize paragraph-wide spacing. `text-align-last`, `match-parent`, CSS display overrides, and vertical writing are unsupported. The alignment fixture is generated by `scripts/make-fixtures.py`; host tests cover stylesheet inheritance, inline isolation, and LTR/RTL placement.

The direction patch carries block-level XHTML `dir` and CSS `direction` into `unicode-bidi` paragraph embedding levels. CSS overrides markup on the same element. Inherit and unset resolve against the parent; initial resolves to LTR. XHTML auto and undeclared direction retain first-strong detection. This undeclared default differs from CSS initial LTR. Inline direction does not change the containing paragraph; inline isolation, embedding, overrides, and `unicode-bidi` remain unsupported. The direction fixture checks inheritance, cascade, escaped attributes, and inline boundaries. Layout tests check logical alignment and mixed Hebrew/Latin visual order without changing source bytes.

Preserved tabs use CSS `tab-size` intervals measured from the paragraph start edge. Nonnegative finite numbers specify space advances; pixel lengths specify absolute intervals. Em lengths resolve against the declaring element's computed font size before inheritance. The normalized interval scales with the reader base size; a child font-size change does not rescale an inherited length. This follows the computed-length model in [CSS tab sizing](https://www.w3.org/TR/css-text-3/#tab-size-property). The default and initial value is eight spaces. Inherit and unset resolve against the parent. Inline overrides apply to each tab. Zero intervals consume the source tab without adding width. Invalid declarations retain the earlier cascade value; unsupported units are ignored. Nonfinite layout intervals or positions return an error. The first source span supplies the paragraph font and scale. Space and zero advances come from that face; missing or zero advances fall back to half an em. A stop less than half a zero advance away advances to the following stop. Layout resolves gaps in paragraph direction after bidi shaping, applies glyph shifts in visual order, and retains tab bytes in source locations without emitting tab glyphs. Measurement and rendering use the same positions. Lines containing tabs skip inter-word justification. Tests cover LTR/RTL paragraphs, scaled fonts, consecutive tabs, near-stop placement, wrapping, and source continuity. Other relative length units, independent containing-block font metrics, and retained trailing tabs remain unsupported. EPUB tests cover fractional, pixel, and em intervals, zero, inheritance across font-size changes, inline overrides, and invalid declarations. The `tab-em.epub` fixture also compares computed lengths with equivalent pixel intervals at multiple reader sizes and exercises pagination reconstruction.

Rustybuzz 0.20.1 shapes text. Swash 0.2.6 rasterizes the resulting glyph IDs. `unicode-bidi` 0.3.18 supplies directional runs; `unicode-linebreak` 0.1.5 supplies break opportunities; `unicode-segmentation` 1.12.0 preserves graphemes during emergency line breaks and font fallback. Optional bold and italic faces use the same layout path. Font fallback is currently coverage-based and does not perform script/language preference ranking.

`unicode-script` 0.5.9 is pinned directly for script segmentation; the same version is already a Rustybuzz dependency in both lockfiles. Its source is `no_std`, MIT OR Apache-2.0, and exposes Script_Extensions intersections and ISO 15924 tags without allocating. The packaged tables report Unicode 18.0.0. Femto adds its own grapheme-preserving run selection and passes the resulting tags to Rustybuzz. This reuses the existing dependency and tables rather than adding an independent Unicode database. Other Unicode processing crates remain separately pinned; classification, segmentation, bidi, font coverage, and shaping are not claimed to implement one uniformly qualified Unicode version.

`hypher` 0.1.8 supplies static hyphenation automata with no runtime dependencies and a Rust 1.64 minimum. Femto enables `alloc`, `english`, `german`, `french`, `spanish`, `italian`, `dutch`, and `portuguese`; the seven packaged tables total 320,760 bytes. Spanish, Italian, Dutch, and Portuguese add 80,562 bytes of static pattern tables over the original English/German/French set. The `alloc` feature prevents the crate's long-word panic, while Femto caps dictionary input at 128 bytes. Compared with loading serialized dictionaries through `hyphenation`, the static-table API avoids dictionary initialization and heap residency on the Picco. The [pinned API](https://docs.rs/hypher/0.1.8/hypher/) and downloaded crate source were inspected before integration. Both host and firmware lockfiles pin this version. The added-language firmware build measured an 80,640-byte increase for monochrome and an 80,656-byte increase for grayscale, including code and alignment changes; both images remain below 5 MB.

Hypher code is MIT OR Apache-2.0; its pattern data have separate notices. Enabled German and French patterns use MIT terms, while American English permits copying with preserved notices. The upstream pattern headers are retained in [English notices](licenses/hypher-en.txt), [German notices](licenses/hypher-de.txt), and [French notices](licenses/hypher-fr.txt). Spanish notices are retained in [Spanish patterns](licenses/hypher-es.txt), Italian notices in [Italian patterns](licenses/hypher-it.txt), and Portuguese notices in [Portuguese patterns](licenses/hypher-pt.txt). Their upstream headers provide MIT, MIT as an available option, and BSD-3-Clause terms respectively. Dutch notices specify LPPL version 1 or later; the [Dutch header](licenses/hypher-nl.txt), [unmodified pinned pattern source](licenses/hypher-nl-source.tex), and [LPPL 1.3c text](licenses/LPPL-1.3c.txt) are retained. The pattern source and generated tables are unmodified. Regional-language distinctions, language-specific spelling transformations, and corpus validation require separate qualification.

Swash is vendored under `vendor/swash` with its Apache-2.0 and MIT licenses. The published archive has SHA-256 `47846491253e976bdd07d0f9cc24b7daf24720d11309302ccbbc6e6b6e53550a`. The local `scale/hinting_cache.rs` patch sets `lcd_subpixel: None` and removes the unused `LcdLayout` import. It retains smooth hinting and linear metrics. The public scaler API does not expose this choice. [E-paper typography](typography.md) records the controls and physical qualification work.

`png` 0.18.1 decodes PNG and writes preview pages. `zune-jpeg` 0.5.15 decodes JPEG directly to luminance, including progressive inputs. Femto owns image resource limits, white alpha compositing, area reduction, placement, ordered dithering and framebuffer packing. Noninterlaced PNG is converted row by row; Adam7 images require a full intermediate frame. These dependencies have host format fixtures but still need peak-memory measurements on the Picco.

The test fixtures include unmodified DejaVu Serif and DejaVu Sans fonts from DejaVu 2.37. Their license is in `tests/fixtures/DejaVu-LICENSE.txt`. The sample text and synthetic illustrations are original to this repository; `scripts/make-fixtures.py` regenerates EPUB, TXT and image fixtures with deterministic ZIP timestamps. The pinned Nix shell includes Pillow for JPEG fixture generation; it is not a runtime dependency.

## Tailscale

`tailscale-esp32` is pinned to `dbd49fe4018023ba07596e4377496718ef21d6ae`. The library is MIT-licensed, uses Rust cryptographic libraries, and keeps its protocol modules independent of ESP-IDF. Femto currently exercises its WireGuard primitives. Runtime control, DERP, discovery, and policy modules are not automatically treated as qualified by including the dependency.

The upstream WireGuard API accepts `SystemTime` and masks the lowest 24 nanosecond bits. Femto's timestamp allocator reserves one persisted epoch per boot and emits 60 distinguishable subsecond ticks before reserving another epoch. This avoids repeated encoded timestamps when handshakes occur rapidly. Storage failure prevents timestamp emission. A single owner must serialize allocation for an identity; identity restoration and legacy migration still need an explicit procedure.

The Unix host store uses `fs2` 0.4.3 for an advisory exclusive process lock and `tempfile` for private temporary records. Identity bytes and the epoch share one atomic, checksummed file. Serialization buffers use `zeroize` 1.9.1. These host dependencies are gated out for ESP-IDF. The store relies on local filesystem rename and fsync semantics; device NVS needs its own backend and qualification. [Identity storage](identity-storage.md) records the format, failure behavior, and backup limits.

The upstream policy schema ignores unknown fields and omits some coordinator semantics. Femto therefore owns a constrained receive-policy parser with explicit supported fields and default denial. It must be wired into authenticated map handling and packet delivery before it provides enforcement in a real client.

CrossPoint, FreeInk SDK, and eikopf/microlink remain behavior and hardware references. No C microlink implementation is linked into the workspace. A full C bridge is not a prerequisite for the Rust client.

## Platform

`minifb` 0.28.0 is an optional dependency behind the host application's `desktop` feature. It displays the reader's CPU framebuffer and supplies keyboard/mouse input; it does not participate in text layout or rasterization. The simulator uses a fixed-size window and redraws book pixels only after state changes. Native event pumping continues at 30 Hz. The pinned Nix shell provides X11/Wayland runtime libraries and Xvfb/xdotool for isolated native-input checks. This backend is excluded from the default CLI build and the reader core. Windows and macOS runtime behavior remains unqualified.

Rust on ESP-IDF remains the planned device configuration. Platform Wi-Fi, verified TLS, native SDMMC, filesystem, and USB services can be reused. Bare-metal Rust is not required for the prototype, and a Rust filesystem crate alone would not provide the Picco's SDMMC host driver.


The upstream `MapStreamDecoder` appends an entire incoming chunk before checking declared message lengths and returns a vector of all decoded responses. Femto's `control_stream` module replaces that boundary with one bounded frame and synchronous per-map delivery. It preserves the pinned implementation's little-endian framing. The reader adapter accepts already-authenticated uncompressed response bodies; it does not establish the coordinator connection.

The upstream `NodeInfo` and `PeerChange` types omit key-expiry fields. Femto owns the authorization-relevant node schema and uses `time` 0.3.44 with parsing and standard-library features for RFC 3339 timestamps. The adapter converts deadlines using a supplied trusted wall/monotonic clock pair and retains node IDs across key replacement. It does not copy the upstream omission into authorization state.

The Unix host TLS adapter pins Rustls 0.23.46, `webpki-roots` 1.0.11, and test-only `rcgen` 0.14.10. Rustls uses the Ring provider with standard-library and TLS 1.2 support; default AWS-LC and certificate-compression features are disabled. Rustls supplies PKI and handshake-signature verification. Femto supplies certificate-name overrides, exact DER certificate pins, socket deadlines, and cancellation. These dependencies are target-gated away from ESP-IDF. The recorded minimum Rust versions are 1.71 for Rustls/root data and 1.88 for rcgen, within the workspace's Rust 1.88 requirement. The lockfile records their transitive dependencies.

The upstream DERP codec retains an HTTP line before checking its header-size limit, permits roughly 1 MiB frames, and skips unknown frames in a receive loop. Femto reuses its protocol encryption and events behind a pre-decoding byte guard, narrower frame limits, and operation deadlines/budgets. Test fixtures use the already-locked `crypto_box` 0.9.1 directly to build server responses and inspect client information. The codec remains pinned rather than vendored or rewritten.

The host coordinator wrapper reuses the pinned `client::ControlConnection` for Noise IK, EarlyNoise, HPACK, and HTTP/2. It supplies verified TLS, absolute deadlines, operation byte budgets, and request/response body limits. The upstream one-MiB HTTP/2 frame allowance remains in effect, and HPACK expansion/peak allocation have not been qualified. The public-service probe tests connection setup only. Reuse does not qualify the upstream client for device memory limits or establish registration/map-stream correctness.

Application networking pins `smoltcp` 0.12.0 with default features disabled and `alloc`, `medium-ip`, `proto-ipv4`, and `socket-tcp` enabled. Its 0BSD license and Rust 1.80 minimum fit the workspace. `Ipv4Repr` and `UdpRepr` provide the existing UDP codec. The TCP engine uses `Interface`, one owned socket, and a bounded IP-medium device. Inspection of the pinned source and in-memory tests cover connection setup, retransmission, stream buffers, half-close, timeout, and packet queue backpressure. Femto retains its UDP bindings and opaque receive queue so coordinator revocation is checked at application release. The TCP owner also binds buffered streams and ciphertext delivery permits to coordinator generations. Managed outbound TCP flows provide exact-tuple reply permissions with connection-owned leases. Full connection-tracking compatibility and application transport integration remain unfinished. The [0.12.0 release](https://github.com/smoltcp-rs/smoltcp/releases/tag/v0.12.0) documents migration to core IP address types and the minimum Rust version. This pins an evaluated API rather than tracking the latest release. This dependency is included in the Picco microlink target build; the firmware does not yet instantiate the tailnet TCP runtime. See [TCP engine](tcp.md) for resource bounds and remaining integration.

## Catalog model

`femto-catalog` uses serde/serde_json and the workspace's existing `url` 2.5.8 version. It projects bounded OPDS 2.0 input into navigation, publication, group, facet, and link records. The `opds` schema crate was considered; a direct projection avoids retaining a separate schema model alongside the reader-facing model. The HTTP adapter reuses `httparse` 1.10.1 and the existing Rustls/Mozilla-root host connector; no new package version was introduced. [Catalog behavior](catalogs.md) records validation and the unfinished network path.

Catalog Basic authentication reuses the workspace's pinned `base64` 0.22.1 and `zeroize` 1.9.1 versions. Zeroize's serde feature wraps decoded credential strings. The Unix CLI uses the existing `libc` 0.2.191 version for no-follow and nonblocking file-open flags. Credentials remain separate from catalog URLs and link models.

Host EPUB acquisition reuses the existing locked `tempfile` crate for temporary files and no-clobber publication. HTTP transfer framing is shared with catalog fetching and writes through a bounded buffer. The reader's explicit EPUB opener validates temporary `.part` files without adding that extension to library scanning.

Keyword search pins [`iri-string` 0.7.14](https://docs.rs/iri-string/0.7.14/iri_string/template/index.html), licensed MIT or Apache-2.0 with a Rust 1.60 minimum. Default features are disabled; the selected template API has no mandatory dependency and does not require its allocating context implementation. The inspected `UriTemplateStr`, `Context`, and `Expanded` APIs validate runtime templates, supply one borrowed scalar, and format into a caller-owned bounded writer. A macro-oriented template crate would not handle arbitrary server-provided templates directly. Femto retains OPDS link selection, input/output caps, URL validation, and the requirement that expansion preserve one complete keyword query parameter. Host tests qualify these behaviors; the Picco firmware uses the same catalog crate.

Host catalog interruption pins [`signal-hook` 0.4.4](https://docs.rs/signal-hook/0.4.4/signal_hook/flag/index.html), licensed MIT or Apache-2.0 with a Rust 1.66 minimum. Default channel and iterator features are disabled. The evaluated flag registration API sets an existing atomic cancellation flag; conditional default handling preserves idle SIGINT behavior. `signal-hook-registry` 1.4.8 is locked transitively and reuses the existing libc and errno dependencies. Command-owned registrations are removed on drop. These dependencies are excluded from ESP-IDF, and no signal handler performs cleanup work directly.

Unix host state ownership reuses the workspace's pinned `fs2` 0.4.3 version. Its inspected `FileExt::try_lock_exclusive` API maps to nonblocking advisory file locking on Unix. A persistent sidecar retains the lock inode across atomic JSON replacement; each owner uses one file handle for its session. The adapter depends on the existing libc version for no-follow and nonblocking open flags. This dependency is excluded from ESP-IDF. [Progress exchange](progress.md) records cooperating-writer scope and filesystem limitations.

The local progress service reuses `httparse` 1.10.1 for request parsing, SHA-256 for strong content ETags, `fs2` for single-owner storage, and the reader's atomic-write routine. `tiny_http` 0.12.0 was inspected but not added: its connection dispatch and worker pool would require separate concurrency and buffering qualification. The prototype uses one accepted stream, explicit header/body caps, and an absolute socket deadline. It is a constrained loopback HTTP/1.1 endpoint rather than a general-purpose server. [Service behavior](progress.md#persistent-local-service) records supported framing and deployment limits.

The local CSS and styled-event patches preserve positive first-line `text-indent` lengths, reset keywords, and block inheritance. Em values are normalized at their declaration using the existing computed font size; inherited values are not rescaled by child font changes. The reader applies the indent once at paragraph start and preserves source anchors. Negative/hanging indents and other unsupported syntax are recorded in [typography support](typography.md#paragraph-indentation).

A shared chapter stylesheet collector retains linked and embedded XHTML CSS in document order. It decodes CDATA and XML references, filters supported media/type declarations, caps sources at 256, and applies a chapter-wide byte limit shared with linked sources. The public book APIs and render preparation share this collector. Linked reads in the public APIs use the remaining chapter byte budget before retaining complete payloads. The styler also applies its rule limit cumulatively and stops parsing before retaining an excess rule. Failed loads clear partial cascades and budget counters. [Chapter stylesheet support](typography.md#chapter-stylesheets) records remaining CSS and memory limits.

The styled-event adapter now emits ordered/unordered list boundaries in addition to item boundaries. Femto retains bounded list counters and per-paragraph marker metadata. Markers are shaped separately from source text, preserving link and reading-position offsets. [List support](typography.md#lists) records the implemented layout and remaining numbering/style variants.

The vendored EPUB styled event stream also emits start/end boundaries for explicit footnote and endnote containers. Namespace resolution distinguishes EPUB type attributes from unqualified or incorrectly bound attributes. The reader adapter converts complete boundaries into source ranges without changing ordinary chapter text or positions. Preview pagination restricts marked bodies while Follow retains the full source chapter.

## Offline dictionary lookup

`quireink-stardict` 0.3.0 is vendored under `vendor/quireink-stardict`; `quireink-platform` 0.3.0 is pinned from crates.io. Both declare Apache-2.0 licensing and Rust 1.85. The downloaded archive SHA-256 values are `c9e13810eed57063d5bc4d07306bcd3176e7074dc442a63fc05325c4e025d8ff` and `cf4050bad0c47b1ba8af11bf50742eef3a69448740e0e898b703e13e0e7a30fb`, respectively. The StarDict archive contains no license file; the vendored directory includes the standard Apache-2.0 text. Package metadata retains the upstream author and repository attribution.

The [pinned dictionary API](https://docs.rs/quireink-stardict/0.3.0/quireink_stardict/) supplies incremental sparse-index construction, headword and synonym lookup, markup-to-text conversion, and dictzip streaming. The platform dependency supplies only storage interfaces to this integration and has no dependencies. Femto provides a filesystem adapter and private in-memory cache files. This avoids a second dictionary parser and persistent index invalidation across dictionary replacement. The [StarDict format reference](https://github.com/huzheng001/stardict-3/blob/master/dict/doc/StarDictFileFormat) defines the source file family.

Local patches propagate declared-synonym open failures, reject definitions exceeding 64 KiB rather than silently truncating them, reject premature EOF for plain definitions, check plain-definition offset addition, use checked conversion for small-file sizes, and check binary-field length addition to reject overflow or truncated payloads. The decompressor dependency moves from 0.8 to the existing patched `miniz_oxide` 0.9.1. Source inspection and targeted host tests support these decisions. The standalone upstream unit and synthetic integration tests pass; a sampled published WikDict English-German corpus also passes through Femto, as recorded in the navigation documentation. Broader interoperability remains unqualified. The metadata patch validates required fields, versions, numeric bounds, duplicate fields, UTF-8, declared index size, and exact prepared entry counts. Index preparation also validates UTF-8 words, ordering, synonym targets, and failure-state handling. Definition decoding now validates field framing and UTF-8 and caps decoded text at 64 KiB while processing fields sequentially. Complete gzip CRC verification and broader markup/encoding compatibility remain unqualified; these patches do not constitute a complete hostile-input audit.

The dictzip patch additionally checks table structure, footer size, selected range arithmetic, complete selected-chunk output sizes, and bounded optional header strings. The generator follows the full-flush chunk structure in [dictd's dictzip implementation](https://sources.debian.org/src/dictd/1.12.1%2Bdfsg-8/dictzip.c). `scripts/make-dictionary-fixture.py` writes a single zlib deflate stream and verifies gzip decompression before saving the fixture. Complete CRC verification remains outside this patch. The adapted upstream fixture uses one full-flush deflate stream with a gzip footer and validates gzip decoding before lookup. Its standalone tests pin flate2 1.1.11 and crc32fast 1.5.4 as development dependencies. The test-only QuireInk SDK and filesystem dependencies are retained from upstream and locked in the vendored Cargo.lock. The normal host and firmware dependency graphs do not include them.

## HID remote input

[`hidreport` 0.6.0](https://docs.rs/hidreport/0.6.0/hidreport/) is pinned with default features disabled and vendored with its MIT license under `vendor/hidreport`. The published archive SHA-256 is `6bba4f2ebef8032ef0125a72c7052481c9d63e50f1d48d35c0933ae11aa58c6d`. Its runtime graph uses `thiserror`; the optional `hut` usage-name tables are disabled. Upstream library tests retain `hut` as a development dependency in the vendor lockfile. The local patch limits Push/Pop to global state and rejects popping the initial state before mutation. Femto owns bounded descriptor preflight, notification framing, press tracking, bindings, and session queues; it reuses semantic HID parsing and bit extraction. [Remote input](remote-input.md) records limits and integration obligations.

Source evaluation and host probes preceded adoption. `hidparser` 1.0.4 was rejected unmodified because the probe reproduced incorrect global-state restoration and a debug arithmetic-overflow panic on an oversized padding descriptor. `hidreport` correctly restores global report count, but the local-usage regression required the patch above. Missing usage pages and short report payloads can panic in its raw APIs; private preflight and framing checks reject those inputs before parser/extractor calls. The patched library passes its 18 upstream unit tests. The external descriptor corpus and complete hostile-input safety remain unqualified.

`esp32-nimble` 0.13.0 was evaluated but is not adopted. Its asynchronous reads retain callback pointers into future-owned state, and discovery retains growable collections. Timeout-by-dropping-future wrappers therefore require further lifetime and cancellation work. ESP-IDF 5.5.2's generic NimBLE HID host also uses blocking waits and dynamically allocated discovery/report data. A bounded callback adapter or explicitly managed worker remains necessary before enabling Bluetooth support. Neither source review establishes a functioning Bluetooth transport.
